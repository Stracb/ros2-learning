## 讲解方式要求（严格遵守）

1. **涉及 Linux 命令时，逐部分说明它在干什么**
   例：`cp -L a b` 要说清 `cp` / `-L` / `a` / `b` 分别是什么。
   **不要默认用户看得懂 `sed` / `grep` / `for` 循环 / `cut` 等。**

2. **讲 ROS 概念时，先讲"它解决什么问题"，再讲怎么用。**

3. **用户说"不懂"时，换个说法重讲，不要重复原话。**

4. **不要一次抛出大量命令**，分步骤给，每步说清预期结果。

5. **主动解释目的**。用户会问"这些步骤是干嘛的"，甚至主动要求"告诉我还有哪些步骤"。

6. **符号规范（第 9 天确定）**：
   - **不要用星星符号**
   - 其他彩色符号可以用（如勾叉）
   - 强调也可以用纯文字："（重要）"、"（注意）"
   > 用户原话（第一次）："少用有颜色的符号表情，例如星星和感叹标识"
   > 用户原话（第 9 天改口）："我还是想着恢复之前那种有颜色的符号表情，只是不要用星星了"

7. **用户明确表示过**："有时候稍微说多一些、节奏快些我也能接受，不懂的我会问"。
   —— 节奏可以适当快，但**关键概念必须讲透**。

8. **每次要写 launch 文件 / 参数文件时，先问一句"走哪一版"（第 10 天用户明确要求）**：
   - **快速版**：`parameters=['/home/pummy/.../xxx.yaml']`（绝对路径写死）+ setup.py 只注册 launch
   - **正规版**：`get_package_share_directory('包名')` 算出路径 + setup.py 注册 `config/`
   > 用户原话（第 10 天）："请以后每次写的时候都请提醒我是否要进行改造。"
   > 意思是：**不要先教土办法、再让他返工改造；一开始就问清楚，直接按选定版本写。**

9. **新增 launch 文件 / 参数文件后，务必提醒两件事**：
   - 注册进 `setup.py` 的 `data_files`（否则 `ros2 launch` 找不到）
   - **改了 setup.py 就必须重编**（第 7 天规则的第二种情况）

# 五、教学法：怎么教这个用户

这部分是项目中最有价值的经验，**新会话请务必照做**。

## 5.1 核心方法：先给结构，再讲细节

**第 3 天的教训**：助手一开始只是"逐行解释代码"，结果让用户做"闭卷重写"时，
用户说"我基本不知道每个类里面有些什么，每个函数是干嘛的" —— **完全写不出来**。

**根因**：用户拿到了一堆零件，但没有图纸。

**现在的做法**：

> **一个节点只有 3 块：**
> | 块 | 名称 | 什么时候跑 | 干什么 |
> |---|---|---|---|
> | 1-A | `__init__` | 创建对象时，一次 | 准备：起名字、建发布者/订阅者/服务、建定时器 |
> | 1-B | 回调函数 | 每次触发，反复 | 干活：造消息、读消息、填 response |
> | 2 | `main()` | 启动时，一次 | 开机 → 造对象 → spin → 清理 |

**讲任何节点前，先把这张"三块图"摆出来。**

## 5.2 新节点用"7 问题推导法"

**不要直接给代码。先让用户回答这 7 个问题：**

| # | 问题 |
|---|---|
| 1 | 节点叫什么名字？ |
| 2 | 要"发"数据吗？发什么？ |
| 3 | 要"收"数据吗？收什么？ |
| 4 | 要"定时"吗？ |
| 5 | 消息/服务/动作类型是什么？ |
| 6 | 要读/填哪些字段？ |
| 7 | 回调里具体干什么？ |

**答完这 7 题，代码自然就出来了。**

**这个方法第 4 天验证有效，之后一直是标准教法。**

## 5.3 卡住时让他翻"清单"，不要翻原代码

- **`05-写节点清单.md`**：只列"该做什么"，不写完整代码 —— 让用户自己回忆语法
- **`06-ROS2命令速查.md`**：命令查询
- **`代码备份/节点模板.py`**、**`launch文件模板.py`**：填空式模板

翻清单是"查语法"，正常；翻原代码是"抄"，效果差。

## 5.4 报错时教他读报错，不要直接给答案

已经教会他识别这些：

| 报错 | 原因 |
|---|---|
| `AttributeError: ... has no attribute 'xxx'` | 方法没缩进到类里 / 名字不一致 / 拼写错误 |
| `UnboundLocalError: ... local variable 'xxx'` | 忘了写 `self.` |
| `Assertion 'PyFloat_Check' failed` + `Aborted` | 浮点字段赋了整数（`2` 应该是 `2.0`）|
| `Package 'xxx' not found` | 终端没 source 工作空间 |
| `No executable found` | 程序名错 / 改了 setup.py 没重编 |
| `could not connect to display` | 在 SSH 终端跑图形程序 |

## 5.5 记忆规律（第 8 天总结出来的，很重要）

对用户做过多次测验，结论非常稳定：

| 内容类型 | 用户表现 | 原因 |
|---|---|---|
| **逻辑 / 原理**（状态机、通信方向、判据）| ✅ **几乎全对** | 理解过就记住 |
| **语法 / 结构**（方法名、文件格式）| ⚠️ **写 1 遍就忘；写 2 遍以上才记住** | 靠重复次数 |
| 环境细节（版本号、配置值）| ❌ 忘 | 不重要，可查 |

**已验证的例子**：

| 内容 | 写过几遍 | 结果 |
|---|---|---|
| 服务端 | 2 遍（`greeter` + `turtle_control`）| ✅ 记得 |
| 状态机 | 3 遍 | ✅ 几乎全对 |
| 客户端 | 1 遍 | ❌ 忘 |
| 参数 | 1 遍 | ❌ 忘 |
| launch | 1 遍 | ❌ 忘 |

> **给新会话的提醒**：
> - **不要强求用户默写只写过 1 遍的东西**
> - **语法类靠"后面用到时自然重复"，不必硬背**
> - 用户自己说过："查表倒是可以知道" —— 这个态度是对的

## 5.6 复习节奏（用户认可）

| 频率 | 做什么 | 时长 |
|---|---|---|
| 每次开场 | 填表复习上次的关键内容 | 5 分钟 |
| 每 3–4 天 | 闭卷重写一个旧节点（挑写过的）| 20 分钟 |
| 每 7 天 | 小整合练习 | 40 分钟 |

**复习用"填表 / 复述 / 闭卷重写"（主动回忆），不要"重读笔记"（被动）。**

# 九、已知的坑（勿重复踩）

| # | 坑 | 真相 |
|---|---|---|
| 1 | ROS 2 装法 | **2025 年后改用 `ros2-apt-source` 包**。网上 `apt-key add` 的老教程已失效 |
| 2 | `apt` 慢到 12.8 kB/s | **不是镜像慢**，是 `security.ubuntu.com` 超时重试拖累。换成国内镜像后变 4,643 kB/s |
| 3 | `grep -r` 找不到 `ros2.sources` | 它是**符号链接**，`grep -r` 默认不跟随，要用 `-R` 或 `cat` |
| 4 | Gazebo 界面频闪 | **Ogre2 与 VMware SVGA3D 不兼容**（与 3D 加速是否开启无关），换 `ogre` 引擎 |
| 5 | 虚拟机不能建在 `E:\VMware\` | 那是**程序安装目录**，权限受限（Everyone 只有 ReadAndExecute）|
| 6 | 快照占空间巨大 | 勾了「拍摄虚拟机内存」，每个快照 12 GB。**取消勾选** |
| 7 | 宿主机 HTTPS 不可用 | 助手的沙箱进程报 `schannel: SEC_E_NO_CREDENTIALS`，只有明文 HTTP 可用（**仅影响助手，不影响用户**）|
| 8 | 浮点字段写整数 | `msg.linear.x = 2` 会崩（`PyFloat_Check` 断言失败）。**必须写 `2.0`** |
| 9 | 客户端和服务端的"谁找谁" | **只有客户端会等**（`wait_for_server`）；服务端只待命，不会卡住 |
| 10 | 改代码何时要重编 | **改已注册文件的内容不用重编**（symlink 生效）；**新增文件 / 改 setup.py 才要重编** |
| 11 | launch 文件里写 `~` | **`~` 只有 shell 会展开，Python 字符串里它就是个普通字符**。必须写真实绝对路径 `/home/pummy/...`，否则 launch 报 `Parameter file path is not a file` |
| 12 | YAML 参数文件"静默失效" | 第 2 层必须是 **`ros__parameters:`（前后各两个下划线）**；写错**不报错**，参数就是读不到。第 1 层必须是**节点名** |
| 13 | GUI 程序在 SSH 终端跑 | `turtlesim_node` / RViz / Gazebo 报 `could not connect to display`。**只能在虚拟机自己的桌面终端跑**（`Ctrl+Alt+T`）|
| 14 | `--symlink-install` 报 `Is a directory` | **接口包（ament_cmake + rosidl）与 `--symlink-install` 天生冲突**（编译时它会自己生成 Python 包目录，软链接覆盖不了目录）。**规则**：编 `my_turtle` 加；编 `my_interfaces` **不加**；全量用 `colcon build`，或 `--symlink-install --packages-skip my_interfaces` |
| 15 | `No executable found` | 三种原因：① `setup.py` 的 `entry_points` 没注册 ② 注册了但**没重编** ③ 编了但当前终端**没 `source ~/ros2_ws/install/setup.bash`** |
| 16 | `ros2 topic echo` 报 `Could not determine the type` | **话题没有发布者——节点没在运行**。节点是**长驻程序**，必须**另开一个终端**一直跑着；一个终端只能跑一个不退出的程序 |
