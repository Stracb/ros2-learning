## 学习原则（先读这个）

1. **不要只看不敲。** ROS 2 的知识 80% 在手指上，不在脑子里。每个概念都要在终端里跑一遍。
2. **报错是主要内容，不是意外。** 卡住超过 40 分钟就去搜/问，但要把完整报错保存下来——这些是你未来的面试素材。
3. **每阶段产出一个可运行的东西。** 不接受"我看懂了"。
4. **代码从第一天就进 git。** 每周至少一次 push 到 GitHub。到求职时你会有 14 周的提交记录，这本身就是能力证明。
5. **不要同时学 C++ 和 Python 两套 API。** 先用 Python（`rclpy`）把概念跑通，阶段十再补 C++（`rclcpp`）。企业里两者都要求，但入门阶段双线并行会拖垮进度。

## 阶段一：ROS 2 核心概念与命令行工具（第 1 周）

### 学习目标

搞清楚 ROS 2 的四个通信机制和一套 CLI 工具。**这一周不写代码。**

### 核心概念

| 概念 | 说明 | 类比 |
|---|---|---|
| Node（节点） | 最小的功能单元 | 一个进程/一个工人 |
| Topic（话题） | 异步、多对多、持续流 | 广播电台 |
| Service（服务） | 同步、一对一、请求-响应 | 打电话 |
| Action（动作） | 长任务、可反馈、可取消 | 下单后追踪物流 |
| Parameter（参数） | 节点的配置项 | 设置面板 |
| DDS / QoS | 底层通信中间件与服务质量策略 | 通信协议 |

### 必须掌握的 CLI

```bash
ros2 run <包名> <可执行名>     # 运行节点
ros2 node list                 # 列出节点
ros2 node info /节点名          # 查看节点的接口
ros2 topic list                # 列出话题
ros2 topic list -t             # 带消息类型
ros2 topic echo /话题名         # 打印话题内容
ros2 topic hz /话题名           # 测发布频率
ros2 topic pub /话题 类型 "数据" # 手动发布
ros2 interface show <类型>      # 查看消息结构
ros2 service list / call       # 服务
ros2 action list / send_goal   # 动作
ros2 param list / get / set    # 参数
ros2 bag record / play         # 数据录制与回放
rqt_graph                      # 可视化节点-话题拓扑
```

### 练习任务

1. 跑通 `turtlesim` + `turtle_teleop_key`，用 `rqt_graph` 看清两个节点之间的关系
2. 用 `ros2 topic pub` 手动发布速度指令，让乌龟走一个正方形（纯命令行，不写代码）
3. 用 `ros2 service call` 调用 `/clear` 服务清屏、`/spawn` 服务生成第二只乌龟
4. 用 `ros2 param set` 修改 turtlesim 的背景色参数
5. 录制一段乌龟运动，用 `ros2 bag play` 回放
6. 阅读 `ros2 interface show geometry_msgs/msg/Twist`，理解消息的嵌套结构

### ✅ 验收标准

- [ ] 能不看笔记说出 Topic / Service / Action 三者的区别，以及各自适用场景
- [ ] 能用纯命令行让乌龟画出一个闭合的正方形
- [ ] 能解释 `rqt_graph` 里每一条连线的含义
- [ ] 能说明 `ros2 bag` 的作用，并完成一次录制+回放
- [ ] 能看懂 `ros2 topic echo` 输出的嵌套消息结构

## 阶段二：编程基础 rclpy / rclcpp（第 2–3 周）

### 学习目标

用 Python 写出真正的 ROS 2 节点，理解发布/订阅、服务、动作、参数的代码实现。

### 学习内容

1. **工作空间与包**
   ```bash
   mkdir -p ~/ros2_ws/src && cd ~/ros2_ws
   ros2 pkg create --build-type ament_python my_first_pkg --dependencies rclpy
   colcon build --symlink-install
   source install/setup.bash
   ```
   > `--symlink-install` 让你改 Python 代码后不用重新 build，强烈建议。

2. **发布者 / 订阅者**：写一个 `Publisher` 节点和一个 `Subscriber` 节点，自定义发布频率与话题名
3. **服务端 / 客户端**：写一个加法服务
4. **动作服务端 / 客户端**：写一个带进度反馈的长任务（如"数到 10，每秒报一次进度"）
5. **参数**：让节点参数可在启动时配置、运行时可动态修改
6. **定时器、日志、命名空间**

### 必做项目：速度控制器

写一个 `velocity_controller` 包：

- 订阅 `/cmd_vel`，发布到 turtlesim
- 提供服务 `/toggle_move` 用于暂停/恢复
- 用参数控制最大速度
- 用日志输出当前状态

### ✅ 验收标准

- [ ] 能独立创建包、写节点、`colcon build`、`ros2 run` 跑起来
- [ ] 能不看示例写出 Pub/Sub、Server/Client 两套代码
- [ ] 理解 `colcon build` 与 `--symlink-install` 的区别
- [ ] 能用 launch 文件同时启动多个节点
- [ ] 代码已推送到 GitHub，且有像样的 README

## 阶段三：自定义接口、Launch 与参数（第 4 周）

### 学习目标

掌握 ROS 2 工程化的三件套：自定义消息、launch 文件、参数管理。

### 学习内容

1. **自定义 msg / srv / action**

   ```
   my_interfaces/
   ├── msg/RobotStatus.msg
   ├── srv/SetMode.srv
   └── action/MoveTo.action
   ```

   关键：正确配置 `package.xml` 的 `<build_depend>` / `<exec_depend>`，以及 `CMakeLists.txt` 的 `rosidl_generate_interfaces`。

2. **Launch 文件**：Python 格式 launch（Jazzy 的主流方式）
   - 启动多个节点
   - 传参、条件启动、命名空间
   - `IncludeLaunchDescription` 复用他人 launch

3. **参数文件**：YAML 外部配置，代替硬编码

4. **生命周期节点（Lifecycle Node）**：`configure → activate → deactivate → cleanup`，Nav2 大量使用

### ✅ 验收标准

- [ ] 能创建自定义 msg/srv/action 并在其他包中正确引用
- [ ] 能写 launch 文件一次启动 3 个以上节点并正确传参
- [ ] 能用 YAML 参数文件配置节点，不修改代码即可改变行为

## 阶段四：URDF/Xacro 机器人建模（第 5 周）

### 学习目标

用代码描述一个机器人——这是所有仿真的前提。

### 学习内容

1. **URDF 基本标签**：`link`、`joint`、`visual`、`collision`、`inertial`
2. **关节类型**：`fixed`、`revolute`、`continuous`、`prismatic`、`floating`
3. **Xacro 宏**：参数化、复用、条件分支——**不要手写纯 URDF，直接学 Xacro**
4. **惯性参数计算**：为什么质量、质心、惯性矩阵很重要（Gazebo 里填错会抖动或飞走）
5. **可视化验证**：`check_urdf`、RViz2 的 RobotModel 显示

### 必做项目：两轮差速小车

建一个标准移动机器人模型：

- `base_link`（车体）
- 左右驱动轮 + 两个万向轮
- 一个激光雷达（`laser_link`）
- 一个深度相机（可选）
- 用 Xacro 参数化轮距、轮径、车体尺寸

### ✅ 验收标准

- [ ] 能用 `check_urdf` 通过校验，RViz2 中正确显示模型
- [ ] 模型使用 Xacro 参数化，改一个参数就能改变尺寸
- [ ] 能解释 `collision` 和 `visual` 为什么要分开
- [ ] 理解惯性矩阵对仿真的影响，能说出填错会怎样

## 阶段五：Gazebo Harmonic 仿真（第 6–7 周）

### 学习目标

把模型放进物理仿真世界，让它动起来。**这是你选择 Jazzy 而非 Humble 的核心收益所在。**

### 学习内容

1. **Gazebo Harmonic 基础**
   ```bash
   gz sim                    # 启动空世界
   gz sim shapes.sdf         # 示例世界
   gz sim -s -r world.sdf    # 无界面 + 立即运行（省资源）
   ```

2. **SDF 世界文件**：地面、光照、物理参数、场景物体
3. **ros_gz 桥接**：ROS 2 与 Gazebo 之间的双向话题桥
   - 配置文件 `bridge_config.yaml` 的写法
   - 常见桥接项：`/cmd_vel`、`/odom`、`/scan`、`/clock`、`/tf`
4. **在 Gazebo 中生成机器人**：`ros_gz_sim create`
5. **调参**：物理步长、实时因子、摩擦系数、接触参数

### 必做项目：让小车在 Gazebo 里跑起来

```bash
# 完整链路：Xacro → URDF → Gazebo → ROS 2 控制
ros2 launch my_robot_description gazebo.launch.py
# 另开终端
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.5}}"
```

小车应当在 Gazebo 中前进，且 `/odom` 有正确输出。

### 常见坑

| 现象 | 原因 |
|---|---|
| 机器人掉进地面 / 飞天 | 惯性参数错误，或 collision 几何体缺失 |
| 轮子打滑不前进 | 摩擦系数太低，或轮子 collision 是圆柱而非带纹理圆柱 |
| Gazebo 极卡 | 3D 加速没生效（回 `01-环境搭建.md` 第 4 步），或物理步长太小 |
| ROS 2 收不到数据 | bridge 配置没写对，或话题名不匹配 |

### ✅ 验收标准

- [ ] 能把自己的 URDF 机器人加载进 Gazebo，且不抖动、不掉落
- [ ] 能通过 `/cmd_vel` 控制小车运动，`/odom` 输出合理
- [ ] 能独立编写 bridge 配置文件并解释每一项
- [ ] 能说出至少 3 个仿真异常的排查方向
- [ ] 能录制一段仿真演示视频（求职会用）

## 阶段八：SLAM 建图（第 10 周）

5. **AMCL**：在已知地图中定位

### 学习目标

5. **控制器**：DWB、Regulated Pure Pursuit、MPPI
6. **恢复行为**：卡住时怎么办（后退、旋转、清代价地图）
7. **调参**：这是 Nav2 最耗时也最能体现水平的部分

### 必做项目：自主导航

在 Gazebo 中建好的地图上，让机器人从 A 点自主导航到 B 点，绕过障碍物。

## 求职准备（第 14 周起）

### 简历怎么写

**不要写**："熟悉 ROS 2，了解 SLAM 和导航"

**要写**：
> 基于 ROS 2 Jazzy + Gazebo Harmonic 搭建两轮差速移动机器人仿真平台，使用 Xacro 参数化建模，通过 ros2_control 实现差速驱动，集成 slam_toolbox 完成未知环境建图（地图精度 X cm），基于 Nav2 实现自主导航与动态避障，自定义行为树实现多目标点巡检任务。项目开源：github.com/xxx/xxx

关键：**技术栈具体 + 有量化指标 + 有开源链接。**

### GitHub 主页

面试官一定会点。确保：

- [ ] 有一个置顶的 ROS 2 项目仓库
- [ ] README 有架构图（画个框图就行）、演示 GIF、安装步骤
- [ ] 提交记录连续（每周都有），不是最后一天一次性提交
- [ ] 有 `.gitignore`，不要把 `build/`、`install/`、`log/` 提交上去

### 高频面试题（务必准备）

**通信机制**
- Topic / Service / Action 的区别与选型
- ROS 2 为什么用 DDS？和 ROS 1 的通信有什么本质区别？
- QoS 策略有哪些？什么场景下需要改 QoS？
- 节点之间通信延迟大，怎么排查？

## 附录 A：Humble 教程 → Jazzy 迁移对照表

你在网上会看到大量基于 Humble 的教程。**大部分概念依然适用**，但下面这些命令和包名必须替换，否则会找不到命令。

### 仿真命令对照

| Humble（Gazebo Classic） | Jazzy（Gazebo Harmonic） |
|---|---|
| `gazebo` | `gz sim` |
| `ros2 launch gazebo_ros gazebo.launch.py` | `ros2 launch ros_gz_sim gz_sim.launch.py` |
| `ros2 run gazebo_ros spawn_entity.py -file x.urdf` | `ros2 run ros_gz_sim create -file x.urdf` |
| 世界文件 `.world` (SDF 1.6) | 世界文件 `.sdf` (SDF 1.10+) |
| `<gazebo>` 标签写在 URDF 里 | 用 `<gazebo>` 仍可，但插件改为 `gz-sim-*` 系列 |
| 插件 `libgazebo_ros_diff_drive.so` | 推荐改用 `ros2_control` + `gz_ros2_control` |
| `gazebo_ros` 包 | `ros_gz_sim` / `ros_gz_bridge` |
| `/gazebo/*` 话题 | `/world/<world_name>/*` 话题 |

### 桥接对照

```bash
# Humble：gazebo_ros 插件直接发布 ROS 话题，无需桥接
# Jazzy：需要显式桥接
ros2 run ros_gz_bridge parameter_bridge /cmd_vel@geometry_msgs/msg/Twist@gz.msgs.Twist
```

或用参数文件：

```yaml
# bridge_config.yaml
- ros_topic_name: "/cmd_vel"
  gz_topic_name: "/cmd_vel"
  ros_type_name: "geometry_msgs/msg/Twist"
  gz_type_name: "gz.msgs.Twist"
  direction: ROS_TO_GZ
- ros_topic_name: "/odom"
  gz_topic_name: "/odom"
  ros_type_name: "nav_msgs/msg/Odometry"
  gz_type_name: "gz.msgs.Odometry"
  direction: GZ_TO_ROS
```

### 识别教程版本的技巧

看教程里出现哪个命令，就知道它是什么年代写的：

| 看到这个 | 说明 |
|---|---|
| `gazebo` / `catkin_make` | ROS 1，**直接关掉** |
| `ament_cmake` + `gazebo_ros` | ROS 2 Humble 或更早 |
| `gz sim` + `ros_gz` | ROS 2 Jazzy 或更新 ✅ |
| `ros2 pkg create` | ROS 2（版本看依赖） |

> **推荐资源**：Articulated Robotics（Josh Newans）的移动机器人系列质量极高，但基于 Humble + Gazebo Classic。**可以看思路和 URDF/Xacro 部分，仿真命令需按上表替换。**

### 建议的查错姿势

1. **先跑 `ros2 doctor --report`**，很多问题它会直接告诉你
2. 复制完整报错（不要只复制最后一行）去搜
