## 一、命令的通用结构

一条 Linux 命令通常是这个形状：

```
命令名   选项        参数
  │       │          │
  ls     -l    /home/<你的用户名>
  │       │          │
 干什么   怎么干     对谁干
```

> **本机用户名是 `pummy`** —— 所以下面出现的 `/home/pummy` 就是 `/home/<你的用户名>`。

| 部分 | 说明 | 例子 |
|---|---|---|
| **命令名** | 要执行什么程序 | `ls`、`cd`、`apt` |
| **选项** | 通常以 `-` 开头，调整行为 | `-l` 详细列表、`-a` 显示隐藏文件 |
| **参数** | 操作对象 | 文件名、目录名、包名 |

> 多个短选项可以合写：`ls -la` 等于 `ls -l -a`

## 二、权限：`sudo` 与 `chmod`

```bash
sudo apt install openssh-server
```

| 部分 | 含义 |
|---|---|
| `sudo` | **SuperUser DO** —— 以"管理员权限"执行后面的命令 |
| `apt install` | 要执行的命令 |
| `openssh-server` | 参数（要装的包名）|

**为什么要 sudo？**
Linux 里"改系统"的操作（装软件、改系统配置、动 `/opt` 里的文件）需要管理员权限。
普通用户直接执行会被拒绝（`Permission denied`）。

>  **sudo 会要密码**。输入时**屏幕上不显示任何字符**（连星号都没有），这是正常的，
> 盲打密码然后回车即可。

### `chmod`：这个文件"谁能读 / 写 / 执行"

`sudo` 是借管理员身份去干活；`chmod` 改的是**文件自己的门锁**（读 / 写 / 执行）。

```bash
chmod +x run.sh         # 让脚本能被执行：./run.sh
chmod 644 notes.txt     # 属主可读可写，同组 / 其他人只读
chmod 755 tools/        # 属主可读可写可执行，同组 / 其他人可读可执行
```

| 写法 | 作用 |
|---|---|
| `chmod +x 文件` | **加执行权限**（`+` 加 / `-` 减 / `x` 执行）。脚本敲 `./脚本.sh` 报 `Permission denied`，就是少了这句 |
| `chmod 644 文件` | 普通文件最常见：属主 读+写；同组、其他人 **只读** |
| `chmod 755 文件或目录` | 可执行文件 / 目录最常见：属主 读+写+执行；同组、其他人 读+执行 |

**数字怎么读：三位 = 文件主人（属主）/ 同组 / 其他人，每一位 = 读 4 + 写 2 + 执行 1。**

| 位上的数 | 拆成 | 权限 |
|---|---|---|
| `7` | 4+2+1 | 读 + 写 + 执行 |
| `6` | 4+2 | 读 + 写 |
| `5` | 4+1 | 读 + 执行 |
| `4` | 4 | 只读 |

> `chmod 644` 读作：属主 `6`（读+写）、同组 `4`（只读）、其他人 `4`（只读）。
> 报 `Operation not permitted` 才是文件不归你，那时才用 `sudo chmod ...`；**平时先不加 `sudo`**。

## 三、文件与目录

| 命令 | 全称/含义 | 作用 | 例子 |
|---|---|---|---|
| `pwd` | **P**rint **W**orking **D**irectory | 我现在在哪个目录 | `pwd` |
| `ls` | **l**i**s**t | 列出目录内容 | `ls`、`ls -la`、`ls -R` |
| `cd` | **c**hange **d**irectory | 切换目录 | `cd ~/ros2_ws` |
| `mkdir` | **m**a**k**e **dir**ectory | 创建目录 | `mkdir -p ~/a/b/c` |
| `cp` | **c**o**p**y | 复制 | `cp a.txt b.txt` |
| `mv` | **m**o**v**e | 移动 / 重命名 | `mv old.txt new.txt` |
| `rm` | **r**e**m**ove | 删除 | `rm file.txt`、`rm -r 目录` |
| `cat` | con**cat**enate | 打印文件全部内容 | `cat package.xml` |
| `nano` | — | 终端里的文本编辑器 | `nano ~/.bashrc` |
| `touch` | — | 创建一个空文件 | `touch test.py` |

### 常用选项

| 选项 | 含义 |
|---|---|
| `-l` | 详细列表（权限、大小、时间）|
| `-a` | 显示隐藏文件（以 `.` 开头的）|
| `-h` | 人类可读的大小（KB/MB/GB）|
| `-R` | 递归（对子目录也生效）|
| `-r` | 递归（`rm`、`cp` 用）|
| `-i` | `rm`：删除前**每个文件都问一次**（要确认就加它）|
| `-I` | `rm`：批量删之前**只问一次**（一次删 >3 个或递归时）|
| `-p` | `mkdir`：父目录不存在就一起创建 |

> ⚠️ **`rm -rf` 是 Linux 里最危险的命令之一。**
> **`rm` 删掉的东西【不进回收站】—— 永久丢失，找不回来。**
>
> - **`-f`（force）= 不提示、不确认，直接删** —— 敲之前**一定先看清楚路径**。
> - **路径里带变量 / 通配符时更危险**：`rm -rf $DIR/` 在 `$DIR` 为空时会变成 `rm -rf /`。
> - **不确定就先 `ls` 看一眼**；真要删，把 `rm -rf` 换成 **`rm -ri`**（每个文件都问一遍），
>   或者 **`rm -I -r`**（一次删多个之前只问一次）。
> - **⚠️ `rm -r` 本身从不询问** —— `-r` 只是"去掉强制"，**不等于"加确认"**；
>   **`-f` 才是"不问"，`-i` / `-I` 才是"问"**。要安全就得自己加 `-i` 或 `-I`。
> - **系统目录（`/`、`/usr`、`/opt`、`/etc`）绝对不要碰。**

### 特殊路径符号

| 符号 | 含义 | 例子 |
|---|---|---|
| `/` | 根目录 | `/opt/ros` |
| `~` | 用户主目录 | `~` = `/home/<你的用户名>`（本机是 `/home/pummy`）|
| `.` | 当前目录 | `./script.sh` |
| `..` | 上一级目录 | `cd ..` |
| `*` | 通配符 | `*.py` 所有 py 文件 |

## 四、软件包管理：`apt`

```bash
sudo apt update
sudo apt install -y ros-jazzy-desktop
```

| 部分 | 含义 |
|---|---|
| `sudo` | 管理员权限 |
| `apt` | Ubuntu 的**软件包管理器** |
| `update` | 子命令：**刷新软件清单**（不是升级！）|
| `install` | 子命令：安装 |
| `-y` | 所有询问自动回答 yes |
| `ros-jazzy-desktop` | 要装的包名 |

### 常用子命令

| 命令 | 作用 |
|---|---|
| `apt update` | 刷新"有哪些软件可装"的清单（**不升级任何东西**）|
| `apt upgrade` | 升级已装的软件 |
| `apt install <包名>` | 安装 |
| `apt remove <包名>` | 卸载 |
| `apt search <关键词>` | 搜索 |
| `dpkg -l <包名>` | **查询某个包装没装** |
| `apt list --installed` | 列出所有已装包 |

> **ROS 2 场景**：查某个 ROS 包有没有装 —— `dpkg -l | grep ros-jazzy`。

> **常见困惑**：`update` 和 `upgrade` 完全不是一回事。
> `update` 只是去网上拿最新的"软件目录"，`upgrade` 才是真的升级。

## 七、管道与重定向（很重要）

### 管道 `|`

**把前一个命令的输出，交给后一个命令处理。**

```bash
dpkg -l | grep ros-jazzy
```
```
dpkg -l 的输出 ──▶ │ ──▶ grep 从里面筛出含 "ros-jazzy" 的行
```

**可以串联多个：**
```bash
dpkg -l | grep ros | head -5
```

### 输出重定向 `>` 和 `>>`

| 符号 | 作用 |
|---|---|
| `>` | 把输出**写入**文件（**覆盖**原内容）|
| `>>` | 把输出**追加**到文件末尾（**不覆盖**）|

```bash
echo "source /opt/ros/jazzy/setup.bash" >> ~/.bashrc
```
↑ 把这句话**追加**到 `.bashrc` 末尾（`>>` 的语法就这么用）

> ⚠️ 上面只是 `>>` 的**语法演示**：ROS 2 实际要写的是**两行**（ROS 2 本体 + 自己的工作空间）。
> **完整的两行写法见 `06-ROS2命令速查.md` §2.0** —— 只写一行，新终端会报 `Package 'my_turtle' not found`。

### 三条标准流与 `2>&1`（第 56 天补）

**每个程序一启动，就带着三条流水线：**

| 编号 | 名字 | 装什么 |
|---|---|---|
| `0` | stdin | 输入（键盘）|
| `1` | stdout | **正常**输出 |
| `2` | stderr | **错误**输出（编译器报错走这条）|

```bash
g++ hello.cpp 2>&1 | head -5
```

| 部分 | 在干什么 |
|---|---|
| `2>` | 把 2 号（错误）改道 |
| `>&1` | 让它指向"**1 号当前指向的地方**" |
| `\|` | 后面接的管道 **只接 1 号** |

**为什么必须这么写**：管道**看不见 2 号**。不加 `2>&1`，编译错误会绕过管道、直接刷满屏，`head -5` 一行都截不到：

| 写法 | 结果 |
|---|---|
| `g++ x.cpp 2>&1 \| head -5` | ✅ 错误并进 1 号 → 被截成 5 行 |
| `g++ x.cpp \| head -5 2>&1` | ❌ `2>&1` 写在管道**之后**，那时 1 号已改道，抄不到 → 满屏 |

> **顺序不能反**：`2>&1` 是"在写下它的**这一刻**，抄一份 1 号的去向"。
> 同类坑：`10-原理与排查方法.md` §5.7「**命令没输出 ≠ 现象不存在**」—— 报错走了 2 号，管道只接 1 号。

## 八、环境变量

```bash
echo $ROS_DISTRO
export MY_VAR=hello
source ~/.bashrc
```

| 部分 | 含义 |
|---|---|
| `echo` | 打印内容 |
| `$ROS_DISTRO` | `$` 表示"取出这个变量的值" |
| `export` | 定义一个环境变量（对当前终端及其子进程有效）|
| `source <文件>` | **在当前终端里执行这个文件** |

### `source` 是 ROS 2 的核心机制

```bash
source /opt/ros/jazzy/setup.bash
```

**它在干什么？** 执行那个 `setup.bash` 文件，而那个文件做的事是：
**把 ROS 2 的各种路径写进环境变量**，比如：

| 环境变量 | 作用 |
|---|---|
| `PATH` | 让终端能找到 `ros2`、`rviz2` 这些命令 |
| `AMENT_PREFIX_PATH` | 让 ROS 2 能找到已安装的包 |
| `PYTHONPATH` | 让 Python 能 `import rclpy` |
| `LD_LIBRARY_PATH` | 让系统能找到 ROS 2 的动态库 |

**不 source 会怎样？** 直接报 `ros2: command not found` —— 因为系统不知道去哪找。

### 为什么必须写 `./` 才能跑自己编的程序（第 56 天补）

**`PATH` 里没有当前目录。** 所以你敲一个**裸名字**时，系统只在 `PATH` 列出的那几个目录里找：

| 你敲 | 系统怎么理解 |
|---|---|
| `avg` | "去 `PATH` 里找有没有叫 `avg` 的命令" → `command not found` |
| `./avg` | "**就在我现在站的这个目录**里找 `avg`" → 找到并执行 |

| 自证命令 | 看什么 |
|---|---|
| `echo $PATH` | 一串用 `:` 隔开的目录 —— **里面没有 `.`** |
| `which avg` | 什么都不输出 = 通讯录上没这个人 |
| `type avg` | 会告诉你它找了哪些地方、都没找到 |

> **`. ` = 当前目录，`..` = 上一层。** `./` 读作"当前目录下的"。
> **Windows 的区别**：Windows 默认会把当前目录也放进搜索范围，所以从 Windows 过来的人几乎 100% 会在这绊一下。
> **不要**为了省事把 `.` 加进 `PATH`：那样你 `cd` 进别人的目录、里面有个叫 `ls` 的坏程序，敲 `ls` 就执行了它 —— 这是 Linux 故意这么设计的。

### `~/.bashrc` 是什么

**`.bashrc` = 每次打开终端时自动执行的文件。** 往里写东西用 `>>`（追加），语法长这样：

```bash
echo "要写进去的那一行" >> ~/.bashrc
```

> **`.bashrc` 到底该写哪两行 → `06-ROS2命令速查.md` §2.0（一次性写全的地方）。**

那两行是：`source /opt/ros/jazzy/setup.bash` + `source ~/ros2_ws/install/setup.bash`。

- **第一行**（ROS 2 本体）：装了 ROS 2 就能写。
- **第二行**（自己的工作空间）：**要等首次编译成功之后再加** —— `install/` 还没生成就写它，
  以后每次开终端都会报 `.../install/setup.bash: No such file or directory`。
- **第二行漏写**：新终端里就是 `Package 'my_turtle' not found`（终端不认识你自己编的包）。

**写完的效果**：新开的终端自动加载，不用再手动 source；**旧终端**要 `source ~/.bashrc` 或重开。

> 只改了 `.bashrc` 但不想重开终端？执行 `source ~/.bashrc` 立即生效。

## 九、终端操作快捷键

| 快捷键 | 作用 |
|---|---|
| `Ctrl + Shift + T` | 新开一个终端标签页 |
| `Ctrl + Shift + W` | 关闭当前标签页 |
| `Ctrl + C` | **终止当前正在运行的程序**（最常用）|
| `Ctrl + L` | 清屏 |
| `Ctrl + Shift + V` | **粘贴**（不是 Ctrl+V！）|
| `Ctrl + A` | 光标跳到行首 |
| `Ctrl + E` | 光标跳到行尾 |
| `Tab` | **自动补全**（命令、文件名都能补，多按几次）|
| `↑` / `↓` | 翻历史命令 |
| `Ctrl + R` | **反向搜索历史命令**（敲几个字就找出以前那条长命令）|
| `history` | **列出用过的历史命令**（带行号）|

> **`Tab` 补全是效率神器。** 打 `cd ~/ros` 然后按 Tab，会自动补成 `cd ~/ros2_ws/`。

### `Ctrl + R` 怎么用（长命令的救星）

**按 `Ctrl + R` → 输入关键词 → 它把最近一条匹配的命令调出来 → 回车直接跑。**

- **继续按 `Ctrl + R`** = 往前找更早的匹配项。
- **按 `→` 或 `Esc`** = 把找到的命令放到行上，**改完再回车**（不直接跑）。
- **按 `Ctrl + C` / `Ctrl + G`** = 取消这次搜索。

`history` 则是把历史**全列出来**（前面带编号）：

```bash
history | grep source      # 从历史里找出所有带 source 的命令
history 20                 # 只看最近 20 条
```

> **`!编号`** 可以直接重跑某一条：`!512` 就是重跑 `history` 里第 512 条。
> **这个功能好用但危险** —— 敲之前先 `history 20` 看一眼那个编号到底是什么。

## 十一、编译一条 C++ 程序（第 56 天起）

**四个阶段，每一步都有产物（默认中间产物会被删掉，只留最后那个）：**

```
avg.cpp ──预处理──▶ avg.i ──编译──▶ avg.s ──汇编──▶ avg.o ──链接──▶ avg（可执行）
          (-E)               (-S)              (-c)             (默认)
```

| # | 阶段 | 产出（后缀）| 里面装什么 | 能跑吗 |
|---|---|---|---|---|
| 1 | **预处理** | **`.i`** | 源码被摊平：`#include` 的内容**整段抄进来**、宏替换、注释删掉（**体积最大**）| 不能 |
| 2 | **编译** | **`.s`** | 汇编指令（**文本**，能打开看）。**类型检查在这一步**，`error:` 都是这步报的 | 不能 |
| 3 | **汇编** | **`.o`** | 机器码 + 符号表 + **重定位信息**（`file` 会说 `relocatable`）。"知道调用什么，但不知道它在哪儿" | **不能** |
| 4 | **链接** | **无后缀** | `.o` + 标准库缝在一起、地址填死、加上入口 → ELF `executable` | **能** |

```bash
g++ hello.cpp -o hello        # 一路到底（中间产物自动删）
g++ -E hello.cpp -o hello.i   # 只要预处理结果
g++ -S hello.cpp -o hello.s   # 只要汇编
g++ -c hello.cpp -o hello.o   # 只要目标文件（不链接）
```

| 选项 | 意思 |
|---|---|
| `-o NAME` | output：指定产物名字。**不写会叫 `a.out`**（1970 年代遗留），多个程序会互相覆盖 |
| `-E` / `-S` / `-c` | 分别"停在"预处理 / 编译 / 汇编之后 |

**三条容易搞混的常识**：

| 想的事 | 事实 |
|---|---|
| "`g++` 会运行我的程序" | **不会**。它只**翻译**。运行是内核干的（`./hello`）|
| "`.h` 头文件也会被编译" | **不会**。它只是被 `#include` 在预处理阶段**抄进 `.i`** |
| "`.o` 可以直接跑" | **不能**。它缺地址、缺库；`./x.o` 会报 `cannot execute binary file` |

> **可执行文件里没有 `cout` 的实现** —— 它只记着"去 `libstdc++.so.6` 里找"。所以拷到别的机器上，那台也得有对应版本的库（"依赖地狱"的起源，`ldd` 能看）。

> **增量编译**就是靠 `.o`：改一个 `.cpp` 只重编那一个，其余 `.o` 不动，最后重新链接一次。CMake / `colcon` 的"只编改过的包"是这个机制的放大版。
