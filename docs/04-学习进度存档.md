> | 天 | 发现 |

> | **44** | **发导航目标时，"朝向"必须与"行进方向"一致** —— 否则到点要原地掉头，而**原地转不算进展** → 判失败 → spin → 更乱。实测 **223.8 s → 112.2 s（2 倍）**（`08` 坑 110）|

> | **38** | ⭐ **QoS：`transient_local` 的发布者，`volatile` 订阅者拿不到历史帧** —— 一天踩三次（RViz / 自写脚本 / `echo`）（`08` 坑 99）|

### 常备参考：一个节点只有 3 块

**（这是第 3 天补的核心结构图，反复会用到，保留在这里）**

| 块 | 名称 | 什么时候跑 | 干什么 |
|---|---|---|---|
| **1-A** | `__init__` | 创建对象时，**一次** | **准备**：起名字、建发布者/订阅者/服务、建定时器 |
| **1-B** | 回调函数 | 每次触发，**反复** | **干活**：造消息、填内容、发出去 / 读消息 / 填 response |
| **2** | `main()` | 启动时，**一次** | 开机 → 造对象 → spin → 清理 |

**调用时序：**

```
main() → rclpy.init() → node = XxxNode() → 【__init__ 执行：准备】
      → rclpy.spin(node) → 定时器响 / 消息到达 / 服务被调用 → 调回调 → 循环
```

**类比：开店**
- `__init__` = 开店准备（挂招牌、装设备、设闹钟）
- 回调函数 = 营业接待（有客人/有订单就处理一次）
- `main()` = 开店流程（开机→造店→运转→打烊）

### 类比：URDF ≈ 前端代码（第 17 天用户自己提的）

> 用户说："**这不就是前端代码吗**" —— **完全正确，而且这个类比对以后很有用**：
>
> | 前端 | URDF / Xacro |
> |---|---|
> | HTML | URDF（声明式结构）|
> | CSS | `<material>` / `<color>` |
> | React 组件 | `<xacro:macro>` |
> | props | `params` |
> | 模板 `${}` | 一模一样 |
> | 构建产物（`dist/`）| **xacro 展开出的 `.urdf`** |
> | DOM 树 | **link/joint 树（运动学树）** |
>
> **唯一的关键区别**：**URDF 多了"物理"这一层** —— `inertial`（质量/惯性）、`joint type`（能不能动）。
> **HTML 只描述"看起来什么样"；URDF 描述"是什么、多重、能怎么动"。**
