# 第一部分：写节点的顺序清单

**从上到下照着走，每一步打勾。**

## □ 第 1 步：三行 import

- [ ] `import rclpy`
- [ ] `from rclpy.node import Node`
- [ ] 从消息包里导入要用的类型（比如 `from geometry_msgs.msg import Twist`）

> 要导入什么类型？看你第 4 步决定了用什么。

---

## □ 第 2 步：定义类

- [ ] `class 类名(Node):` —— **必须继承 `Node`**
- [ ] 类名首字母大写

---

## □ 第 3 步：写 `__init__`（配置块，跑一次）

**逐个问自己：**

- [ ] **名字** → `super().__init__('节点名')`
- [ ] **要发数据吗？** → 是 → 建**发布者**
- [ ] **要收数据吗？** → 是 → 建**订阅者**
- [ ] **要定时做事吗？** → 是 → 建**定时器**
- [ ] 打个招呼 → `self.get_logger().info('...')`

>  **`__init__` 里不发任何消息** —— 这里只是"把工具准备好"。

---

## □ 第 4 步：写回调函数（干活块，反复跑）

** 两个致命细节：**

- [ ] **缩进 4 格**，和 `def __init__(self):` **左边对齐**（在类里面！）
- [ ] 如果是**订阅者**的回调，参数里要有 `msg`

**里面逐个问自己：**

- [ ] **要做什么？** → 造消息 / 读消息
- [ ] **填什么值 / 读什么字段？** → `msg.xxx = 值` 或 `读 msg.xxx`
- [ ] **要发出去吗？** → `self.发布者名.publish(msg)`

>  **定时器/订阅者里写回调函数名时，不要加括号！**
> `self.create_timer(0.1, self.回调名)` ← 没有 `()`

---

## □ 第 5 步：类外面的 `main()`（启动流程，跑一次）

** 缩进 0 格 —— 在类外面！**

- [ ] `rclpy.init()`
- [ ] `node = 类名()`
- [ ] `rclpy.spin(node)`
- [ ] `node.destroy_node()`
- [ ] `rclpy.shutdown()`

---

## □ 第 6 步：最后的调用

- [ ] `if __name__ == '__main__':`
- [ ] 下一行缩进 4 格：`main()`

---

## □ 第 7 步：注册到 `setup.py`

- [ ] 在 `entry_points` 的 `console_scripts` 里加一行：`'程序名 = 模块名.文件名:main',`
- [ ] **注意上一行末尾要有逗号**

## □ 第 8 步：编译运行

- [ ] **改了 setup.py → 必须先重编**：`cd ~/ros2_ws && colcon build --packages-select <包名> --symlink-install`
- [ ] 只改了 `.py` 内容 → 不用重编
- [ ] 跑：`ros2 run 包名 程序名`
- [ ] **改了【接口】**（`my_interfaces` 的 `.msg`/`.srv`）→ 编 `my_interfaces`，**不加 `--symlink-install`**（`08` 坑 47）

# 第二部分：语法形状（忘了怎么写的时候查这里）

**你只需要记"形状"，不用背整行。**

## 形状 1：起名字（在 `__init__` 里）

```
super().__init__('节点名')
```

## 形状 2：建发布者（要"发"数据时）

```
self.变量名 = self.create_publisher(
    消息类型,
    '话题名',
    10
)
```

## 形状 3：建订阅者（要"收"数据时）

```
self.变量名 = self.create_subscription(
    消息类型,
    '话题名',
    self.回调函数名,
    10
)
```

>  回调函数名**不加括号**
>  订阅者的回调函数，参数里要有 `msg`：
> ```
> def 回调名(self, msg):
> ```

## 形状 4：建定时器（要"定时"做事时）

```
self.变量名 = self.create_timer(
    间隔秒数,
    self.回调函数名
)
```

>  回调函数名**不加括号**

## 形状 5：造消息 + 填字段 + 发出去（在回调里）

```
msg = 消息类型()
msg.字段.子字段 = 值
self.发布者变量名.publish(msg)
```

>  **小数一定要写小数点**：`2.0` 不能写 `2`（否则 C 层断言失败，程序 Abort）

## 形状 6：读收到的消息（订阅者回调里）

```
def 回调名(self, msg):
    self.get_logger().info(f'收到: {msg.字段名}')
```

## 形状 7：主流程（固定不变）

```
def main():
    rclpy.init()
    node = 类名()
    rclpy.spin(node)
    node.destroy_node()
    rclpy.shutdown()


if __name__ == '__main__':
    main()
```

## 形状 8：建服务端（要"提供"服务时） 第 4 天补充

```
self.变量名 = self.create_service(
    服务类型,
    '服务名',
    self.回调函数名
)
```

>  **只有 3 个参数**（没有队列长度！）
>  回调函数名**不加括号**

## 形状 9：服务回调函数  第 4 天补充

```
def 回调名(self, request, response):
    # 读 request 里的字段（如果 srv 的请求部分是空的，就没得读）
    某变量 = request.字段名

    # 填 response 的字段
    response.字段1 = 值
    response.字段2 = 值

    return response          #  必须返回！不返回对方会一直卡着
```

>  **回调参数是两个**：`request` 和 `response`（订阅者只有一个 `msg`）
>  **必须 `return response`**

**导入服务类型的写法（注意是 `.srv`）：**

```
from 包名.srv import 服务名
```

例：`from std_srvs.srv import Trigger`

## 形状 10：声明参数（在 `__init__` 里） 第 6 天补充

```
self.declare_parameter('参数名', 默认值)
```

## 形状 11：读参数值  第 6 天补充

```
self.变量名 = self.get_parameter('参数名').value
```

>  **末尾的 `.value` 不能少** —— 少了它拿到的是"参数对象"，不是值。
>  **ROS 2 规定：不先 `declare` 就不能 `get`。**

## 形状 12：launch 文件骨架  第 7 天补充

```python
from launch import LaunchDescription
from launch_ros.actions import Node


def generate_launch_description():          #  函数名不能改
    return LaunchDescription([
        Node(
            package='包名',

            name='节点名',                    # 可选
            output='screen',                  # 把日志打到终端
        ),
        # 要几个节点写几个 Node(...)
    ])
```

## 形状 14：建服务**客户**端（在 `__init__` 里） 第 8 天补充

```
self.client = self.create_client(服务类型, '服务名')
```

> **只有 2 个参数** —— 没有回调函数！（客户端是主动方，自己发起自己等）

## 形状 15：发送请求并等响应  第 8 天补充

### 先看【放在哪】—— 这是骨架，比语法重要

```
class XxxClient(Node):
    def __init__(self):
        super().__init__('节点名')
        self.client = self.create_client(服务类型, '服务名')   # ← 形状 14
        #  __init__ 里【不发送】请求，只建客户端

    def send_request(self, value):        # ← 发送逻辑写成【单独的方法】
        # 形状 15 的五步写在这里
        ...


def main():
    rclpy.init()
    node = XxxClient()
    node.send_request(True)               # ← 在这里调用（传你要的参数）
    node.destroy_node()
    rclpy.shutdown()

# main() 里【没有 rclpy.spin(node)】—— 客户端不需要一直运行
```

**和发布者/订阅者的区别：**

| | 发布者/订阅者 | **客户端** |
|---|---|---|
| `__init__` 里 | 建发布者/订阅者 | **只建客户端** |
| 干活在哪 | **回调里**（被 ROS 2 调用）| **普通方法里**（你自己调用）|
| `main()` 里 | **必须有 `rclpy.spin`** | **不要 `spin`** |

> **为什么客户端不用 spin？** 因为它是"主动方" —— 发一次请求、等结果、结束。
> **不需要一直待命等别人调用。**

### 五步代码（写在上面那个方法里）

```
# ① 等服务端上线（不能省！否则后面会失败）
while not self.client.wait_for_service(timeout_sec=1.0):
    self.get_logger().info('等待服务...')

# ② 造请求 + 填字段
request = 服务类型.Request()
request.字段名 = 值

# ③ 发送（异步）
future = self.client.call_async(request)

# ④ 等响应回来
rclpy.spin_until_future_complete(self, future)

# ⑤ 取出响应
response = future.result()
self.get_logger().info(f'返回: {response.字段名}')
```

> **`future` 是"取餐号码牌"** —— 代表"还没到达的结果"。
> `call_async` 给你号码牌，`spin_until_future_complete` 等它做好，`result()` 取出结果。
>
>  **客户端的 `main()` 里不需要 `rclpy.spin(node)`** —— 发完请求拿到响应就可以退出了。

## 形状 16：YAML 参数文件  第 10 天补充

**放哪儿**：包根目录下的 `config/` 文件夹，如 `my_turtle/config/circle_params.yaml`

**长什么样**（三层，一层比一层往里缩 2 个空格）：

```yaml
draw_circle:                  # 第 1 层：节点名（顶格，不加引号）
  ros__parameters:            # 第 2 层：固定关键字（前后各两个下划线）
    linear_speed: 6.0         # 第 3 层：参数名: 值
    angular_speed: 3.0
```

**三个要点（错一个就静默失效 —— 最阴的坑）**：

1. 第 1 层必须是**节点名**，要和 `super().__init__('...')` 里那个名字**一模一样**
2. 第 2 层固定写 `ros__parameters:` —— **前后各两个下划线**（注意）。写错**不报错**，但参数就是读不到
3. `参数名:` 后面**必须有一个空格**再写值；缩进只能用**空格**，不能按 Tab

**怎么用（命令行）**：

```bash
ros2 run my_turtle draw_circle --ros-args --params-file /home/pummy/ros2_ws/src/my_turtle/config/circle_params.yaml
```

> `--params-file` = "指定参数文件"，后面跟**文件的绝对路径**。
> 用绝对路径最保险 —— 相对路径会跟着"你在哪个目录敲命令"变，容易找不到。

**怎么用（launch 文件里，更常用）**：

```python
Node(
    package='my_turtle',
    executable='draw_circle',
    output='screen',
    parameters=['/home/pummy/ros2_ws/src/my_turtle/config/circle_params.yaml'],
)
```

> **三种参数写法对照（千万别混）**
>
> | 场景 | 格式 |
> |---|---|
> | 命令行 | `-p linear_speed:=6.0`（`:=`）|
> | launch 文件 | `{'linear_speed': 6.0}`（Python 字典，冒号）|
> | YAML 文件 | `linear_speed: 6.0`（冒号 + 空格）|

## 形状 17：参数文件路径的"正规做法"  第 10 天补充

**两版并存的现实**：先用快速版跑通，再改正规版没必要 —— **一开始就选一版**。

### 快速版（能跑，但把家目录写死了）

```python
parameters=['/home/pummy/ros2_ws/src/my_turtle/config/circle_params.yaml'],
```

> 缺点：换用户名 / 换目录名 / 换电脑就崩。

### 正规版（推荐；正规 ROS 2 仓库都这么写）

**① launch 文件里**：

```python
import os
from ament_index_python.packages import get_package_share_directory


def generate_launch_description():
    config_file = os.path.join(
        get_package_share_directory('包名'),   # 问 ROS：这个包装到哪了
        'config',                               # 往里走一级
        'xxx.yaml'                              # 文件名
    )

    return LaunchDescription([
        Node(
            package='包名',
            executable='程序名',
            output='screen',
            parameters=[config_file],           # ← 用算出来的路径
        ),
    ])
```

**② `setup.py` 里必须注册 `config/`**（否则它不会进 `install/`）：

```python
('share/' + package_name + '/config', ['config/xxx.yaml']),
```

**③ 改了 setup.py 就必须重编**：

```bash
colcon build --packages-select 包名 --symlink-install
```

**④ 验证装进去了**：

```bash
ls ~/ros2_ws/install/包名/share/包名/config/
```

> **注意（第 10 天用户要求）**：每次要写 launch / 参数文件时，
> **先问用户走"快速版"还是"正规版"**，不要先给土办法再返工。

## 形状 18：自定义接口的完整流程  第 11 天补充

**接口必须放在一个单独的【CMake 包】里** —— Python 包做不到（生成接口代码的工具链只挂在 CMake 上）。

### 一次性准备：建接口包

```bash
cd ~/ros2_ws/src
ros2 pkg create --build-type ament_cmake my_interfaces
mkdir -p ~/ros2_ws/src/my_interfaces/msg
mkdir -p ~/ros2_ws/src/my_interfaces/srv
```

### 加一个接口：改 3 个地方

| # | 文件 | 改什么 |
|---|---|---|
| 1 | `msg/Xxx.msg`（新建）| 字段清单：一行一个 `类型 字段名`（`#` 后是注释）|
| 2 | `CMakeLists.txt` | 见下方三段 |
| 3 | `package.xml` | 见下方三行 |

**`CMakeLists.txt` 加这三段**（必须放在 `ament_package()` **之前**）：

```cmake
find_package(rosidl_default_generators REQUIRED)

rosidl_generate_interfaces(${PROJECT_NAME}
  "msg/Xxx.msg"
  "srv/Yyy.srv"
)

ament_export_dependencies(rosidl_default_runtime)
```

> ⚠️ **列表项之间不加逗号**（注意）—— CMake 的列表是用**空格/换行**分隔的，
> 不是逗号。写了逗号会报
> `rosidl_generate_interfaces() the passed file ',' doesn't exist`。
> 见 `08-踩坑总集.md` **坑 58**。
>
> **三种文件的列表写法对照**：
> | 文件 | 分隔方式 |
> |---|---|
> | Python（`setup.py`）| **逗号** `['a', 'b']` |
> | YAML | 换行 + 缩进 |
> | **CMake（`CMakeLists.txt`）** | **空格 / 换行，不要逗号** |

**`package.xml` 加这三行**（放在 `</package>` **之前**）：

```xml
<build_depend>rosidl_default_generators</build_depend>
<exec_depend>rosidl_default_runtime</exec_depend>
<member_of_group>rosidl_interface_packages</member_of_group>
```

### `.srv` 和 `.msg` 的唯一区别：中间一条 `---`

```
# 请求（客户端 → 服务端）
int32 sides
float64 side_length
---
# 响应（服务端 → 客户端）
bool success
```

`.action` 更复杂（三段），以后再说。

### 编译 + 验证（注意：接口包**不加** `--symlink-install`）

```bash
cd ~/ros2_ws
colcon build --packages-select my_interfaces
source ~/ros2_ws/install/setup.bash
ros2 interface show my_interfaces/msg/Xxx
```

> **为什么不能加 `--symlink-install`**：接口包编译时会自己生成一个 Python 包目录，
> 软链接覆盖不了已有目录 → 报 `existing path cannot be removed: Is a directory`。

### 在别的包（Python 包）里使用：改 2 处 + 新建 1 文件

| # | 位置 | 写什么 |
|---|---|---|
| 1 | `my_turtle/package.xml` | `<depend>my_interfaces</depend>` |
| 2 | `my_turtle/setup.py` 的 `entry_points` | `'程序名 = my_turtle.文件名:main',` |
| 3 | `my_turtle/my_turtle/新文件.py` | import 并收发 |

然后重编：**`colcon build --packages-select my_turtle --symlink-install`**
（新增文件 + 改了 setup.py，两个条件都占了）

### import 规律（记这一条就够）

```python
from my_interfaces.msg import TurtleStatus     # 消息
from my_interfaces.srv import DrawPolygon      # 服务
```

> **`from 包名.类型目录 import 类型名`**
> **类型名 = 你建的 `.msg` / `.srv` 文件名（去掉后缀）。**
> **没有那个文件，就没有那个类** —— 类不是凭空来的，是编译时生成的。

### 别忘：接口包需要在 Git 里提交

`my_interfaces/` 是**新的一个包**，`git add .` 会把它一起收进去。这是好事。

## 形状 19：动作**客户**端  第 11 天补录（第 9 天学的）

> **补录说明**：第 9 天写了 `rotate_client` / `my_rotate_server`，但当时没把形状存进这份清单。
> 第 11 天审计时发现这个缺口，现补上。**命名以你实际的代码为准。**

**和"服务客户端"最大的区别**：动作是**长任务**，要处理三种消息 ——
**目标是否被接受** / **过程中的反馈** / **最终结果**。所以有**三个回调**。

### ① import + 建客户端（在 `__init__` 里）

```python
from rclpy.action import ActionClient

self._action_client = ActionClient(
    self,
    动作类型,          # 如 RotateAbsolute
    '动作名'           # 如 '/turtle1/rotate_absolute'
)
```

> **只有 2 个参数**（`self` 之后）—— 和 `create_client` 一样，**不给回调**。

### ② 发送目标（写在 `main()` 里，不在回调里）

```python
goal_msg = 动作类型.Goal()          # ① 造目标
goal_msg.字段名 = 值                # ② 填字段

self._action_client.wait_for_server()   # ③ 等服务端上线（不能省）

self._send_goal_future = self._action_client.send_goal_async(
    goal_msg,
    feedback_callback=self.feedback_callback    # ④ 挂上"反馈回调"
)
self._send_goal_future.add_done_callback(self.goal_response_callback)   # ⑤
```

### ③ 三个回调

| 回调 | 什么时候被调用 | 干什么 |
|---|---|---|
| `goal_response_callback(self, future)` | 服务端**表态**"接不接" | 接了 → `goal_handle.get_result_async()` 去等结果 |
| `feedback_callback(self, feedback_msg)` | 执行**过程中**反复调用 | `feedback_msg.feedback.字段名` 读进度 |
| `get_result_callback(self, future)` | **最终结果**回来 | `future.result().result.字段名` 读结果 |

```python
def goal_response_callback(self, future):
    goal_handle = future.result()
    if not goal_handle.accepted:
        self.get_logger().info('目标被拒绝')
        return
    self._get_result_future = goal_handle.get_result_async()
    self._get_result_future.add_done_callback(self.get_result_callback)


def feedback_callback(self, feedback_msg):
    self.get_logger().info(f'进度: {feedback_msg.feedback.字段名}')


def get_result_callback(self, future):
    result = future.result().result
    self.get_logger().info(f'结果: {result.字段名}')
    rclpy.shutdown()
```

### ④ `main()` 里**还是要 `spin`**（注意）

```python
rclpy.spin(node)
```

> **动作客户端 vs 服务客户端，这是关键区别：**
>
> | | 服务客户端 | 动作客户端 |
> |---|---|---|
> | `main()` 里要 `spin` 吗 | ❌ **不要**（发一次、拿结果、退出）| ✅ **要**（一直待命，收反馈和结果）|

### 一句话记忆

> **动作 = 服务 + 反馈 + 可取消。**
> 所以客户端多出来的东西，全都和"**过程**"有关 —— 就是 `feedback_callback`。

## 形状 20：动作**服务端**  第 11 天补录（第 9 天学的）

### ① import + 建服务端（在 `__init__` 里）

```python
from rclpy.action import ActionServer

self._action_server = ActionServer(
    self,
    动作类型,          # 如 RotateAbsolute
    '动作名',          # 如 'my_rotate'
    self.execute_callback
)
```

> **形状和 `create_service` 很像**：类型 + 名字 + 回调。

### ② 唯一的回调：`execute_callback`

```python
def execute_callback(self, goal_handle):
    # ① 读目标
    self.get_logger().info(f'目标: {goal_handle.request.字段名}')

    # ② 干活；过程中可以发反馈（不是必须）
    feedback_msg = 动作类型.Feedback()
    feedback_msg.remaining = 值
    goal_handle.publish_feedback(feedback_msg)

    # ③ 宣布成功（也有 .abort() / .canceled()）
    goal_handle.succeed()

    # ④ 造结果并 return（不能省！）
    result = 动作类型.Result()
    result.字段名 = 值
    return result
```

### 和服务端对比（一张表看清）

| | 服务回调 | 动作回调 |
|---|---|---|
| 回调名字 | 你自己起 | 你自己起（约定用 `execute_callback`）|
| 参数 | `(self, request, response)` | `(self, goal_handle)` |
| 目标/请求在 | `request` | `goal_handle.request` |
| 中间反馈 | ❌ 没有 | ✅ `goal_handle.publish_feedback(...)` |
| 怎么表态 | `return response` | `goal_handle.succeed()` **+** `return result` |
| 能取消吗 | ❌ | ✅ `goal_handle.is_cancel_requested` |

```bash
ros2 action send_goal /my_rotate turtlesim/action/RotateAbsolute "{theta: 1.5708}" --feedback
```

> `--feedback` = 把过程中的**反馈**也打印出来（不加就只看最终结果）。

> `src/my_turtle/my_turtle/rotate_client.py` 和 `my_rotate_server.py` 里的实际写法为准。

# 第五部分：命名规范 （第 4 天补充）

## 各种名字的大小写规则

| 什么东西 | 规则 | 例子 | 对照 |
|---|---|---|---|
| **Python 类名** | **首字母大写**（大驼峰）| `TurtleCircler` `PoseReader` `PubSub` | ✅ |
| **ROS 包名** | 全小写 + 下划线 | `my_turtle` `nav2_bringup` | ✅ |
| **ROS 节点名** | 全小写 + 下划线 | `turtle_circler` `pub_sub` | ✅ |
| **话题名** | 全小写 + 下划线 + 用 `/` 分层 | `/turtle1/cmd_vel` | ✅ |
| **Python 文件名** | 全小写 + 下划线 | `draw_circle.py` | ✅ |
| **Python 函数/变量** | 全小写 + 下划线 | `read_pose` `cmd` | ✅ |

### 一句话记住

> **只有【类名】首字母大写，其他全部小写 + 下划线。**

| 写法 | 对不对 |
|---|---|
| `class PoseReader(Node):` | ✅ |
| `class pose_reader(Node):` | ❌ 类名该大写 |
| `super().__init__('pose_reader')` | ✅ 节点名小写 |
| `super().__init__('PoseReader')` | ❌ 节点名不该大写 |
| `self.create_publisher(...)` | ✅ 方法名小写 |
| `/turtle1/cmd_vel` | ✅ 话题名小写 |

## 节点的"三个名字"，不需要一样

一个节点其实有**三个**相关的名字，**可以不同**：

| 名字 | 写在 | 例子 | 作用 |
|---|---|---|---|
| **文件名** | 磁盘上的 `.py` | `wall_stopper.py` | Python 找文件用 |
| **程序名** | `setup.py` 的 `entry_points` | `wall_stopper` | `ros2 run` 时用 |
| **节点名** | `super().__init__('...')` | `pub_sub` | `ros2 node list` 里显示 |

**你的 `PubSub` 就是这样：文件名可能叫 `wall_stopper.py`，程序名 `wall_stopper`，但节点名是 `pub_sub`。**

**三个名字可以完全不同，互不影响。**

> **建议**：初学阶段**三个保持一致**，少一个记忆负担。
> 等熟了再根据需要区分（比如一个文件里放多个程序时，就必须区分了）。

## 话题名的"/"开头是什么意思

| 写法 | 叫法 | 含义 |
|---|---|---|
| `/turtle1/cmd_vel` | **绝对名称** | 从根开始，不受命名空间影响 ✅ **推荐** |
| `turtle1/cmd_vel` | **相对名称** | 相对于节点所在命名空间 |

**不加 `/` 也能跑**（因为你的节点在根命名空间下），
**但加了更安全** —— 以后把节点放进命名空间（多机器人场景）时会出问题。

**建议：写话题名时一律加开头的 `/`。**

# 第八部分：节点到底是怎么"运行"起来的  第 12 天补充

> 到第 12 天，一个文件里已经能同时有**服务端 + 订阅者 + 状态机**了。
> 那它跑起来的时候，**到底是谁、在什么时候、被谁叫**？
> （这个问题是用户第 12 天自己提出来的，说明开始关心"运行时模型"了。）

## 核心：一个节点 = 一个"等 → 处理 → 回去等"的循环

```python
def main():
    rclpy.init()                 # ① 初始化 ROS 2
    node = PolygonDrawer()       # ② 造对象 → __init__ 只跑一次
                                 #    ★ 它只"登记"：建发布者/订阅者/服务
    rclpy.spin(node)             # ③ ★在这里待命★ —— 不会自己返回
    node.destroy_node()          # ④ 只有 Ctrl+C 之后才走到这里
    rclpy.shutdown()
```

**`rclpy.spin()` 像一个"前台接待员"**：

> **它不主动找事做，只是"等人上门"。**
> 有人来了 → 派给对应的回调 → 回去继续等。

## 谁能"叫醒"节点？—— 只有四类事件

| 事件来源 | 触发哪个回调 | 什么时候来 |
|---|---|---|
| **订阅的话题有新消息** | 订阅回调 | 别人一直在发，就一直来 |
| **别人调用你的服务** | 服务回调 | **只有被调用时才来** |
| **别人发动作目标** | `execute_callback` | 同上 |
| **定时器到点** | 定时器回调 | 每隔 N 秒来一次 |

## 对照：你写过的节点靠什么被叫醒

| 节点 | 靠什么被叫醒 | 要不要定时器 |
|---|---|---|
| `draw_circle` | **没人叫它** | ✅ **必须自己加** |
| `read_pose` | Pose 消息 | ❌ |
| `greeter` | 服务被调用 | ❌ |
| `draw_polygon` | **两者都有**：Pose 消息 + 服务被调用 | ❌ |

> **规律：如果你的节点"没人叫"，就必须自己加定时器。**

## 完整时间轴：一次"画五边形"到底发生了什么

```
t=0.000s   main() → init → __init__ 跑完 → spin 开始待命
──────────── 待机阶段（self.state = 'idle'）────────────
t=0.001s   收到 Pose → handle_subs → 'idle' → 发【零速度】
t=0.017s   收到 Pose → handle_subs → 'idle' → 零速度
   ...     每秒 62 次，全是零速度 → 乌龟纹丝不动
──────────── 你敲下 ros2 service call ────────────
t=5.000s   收到【服务请求】→ handle_srv：
              存 sides_ / length_
              重置 cnt / start_x / start_y / start_theta
              self.state = 'forward'     ← ★ 状态机被"点火"
              return response            ← 立刻返回（不阻塞！）
──────────── 干活阶段（'forward' / 'turn'）────────────
t=5.017s   收到 Pose → 'forward' → 发【前进速度】→ 乌龟动起来
   ...     每秒 62 次：边跑边判断"走够了吗 / 转够了吗"
t=12.000s  cnt 到 5 → self.state = 'done'
──────────── 收工阶段 ────────────
   ...     之后每次 Pose 都走 else → 发零速度 → 乌龟停下
```

## 所以"为什么调用服务才动"？—— 准确答案

> **不是"没运行"！`handle_subs` 一直在跑（每秒 62 次）。**
> **而是"待机状态下它什么也不干"** —— 只发零速度。
>
> **服务回调是唯一能把状态机从 `'idle'` 推进到 `'forward'` 的地方。**
> **你不点这个火，它就一直待机。**

## 为什么服务回调必须"立刻返回"（重要的设计约束）

因为**前台接待员只有一个人**（`rclpy.spin` 默认单线程）：

```
服务回调卡住 → 前台忙着 → Pose 消息排队 → operation 跑不了
            → 乌龟不动 → 永远画不完 → 服务回调永远等 → 死锁
```

**所以分工是一条铁律**：

| 角色 | 干什么 | 时长 |
|---|---|---|
| **服务回调** | 下达任务 + 点火 | **立刻返回**，不能阻塞 |
| **订阅回调** | 一次一小步地干活 | 每次都很短，被反复调用 |

> **想让"任务做完之后"再返回结果？→ 那要用【动作（Action）】，不是服务。**
> 详见 `08-踩坑总集.md` **坑 61**。

## 一句话总结

> **节点是"被动的"** —— 它不主动跑，只是**一直待命，等人叫它**。
> **`__init__` 负责"登记"，`spin` 负责"接待"，回调负责"干活"。**

# 第九部分：`goal_handle` / `node` 这类【运行时对象】怎么查  第 13 天补充

> 用户第 13 天问的："**我记不得 `goal_handle` 有哪些字段，怎么知道一个函数有哪些东西？**"

## 先分清两种东西（这是关键）

| 你面对的 | 例子 | 怎么查 |
|---|---|---|
| **接口类型的字段** | `msg.x`、`request.sides`、`feedback.distance_remaining` | **`ros2 interface show <类型>`**（第七部分）|
| **ROS 运行时给你的对象** | **`goal_handle`**、`node`、`future` | **不能用 `interface show`！** 用下面的办法 |

> **为什么 `ros2 interface show` 对 `goal_handle` 无效**：
> 它**不是接口类型**，是 `rclpy` 给你一个 **Python 对象**。
> `interface show` 只认 `.msg` / `.srv` / `.action` 那些"数据类型"。

## 三个"自己查"的办法（按好用程度排）

### ① VS Code 自动补全 —— 最快，首选

**打 `goal_handle.` 然后按 `Ctrl+Space`**，列表直接弹出来。

> **没有工程师背 API 名字，大家都是让 IDE 补全。**（第三部分也说过这条）

### ② `dir(对象)` —— 在代码里打印出来看

```python
# 临时加一行
self.get_logger().info(str([x for x in dir(goal_handle) if not x.startswith('_')]))
```

`dir(obj)` = 列出这个对象的**所有属性和方法名**。
`if not x.startswith('_')` = **过滤掉 `__init__`、`__str__` 这类内部名字**，只留有用的。

跑一次，挑有用的看，**看完把那行删掉**。

### ③ `help(类)` —— 看说明书

```bash
python3 -c "from rclpy.action.server import ServerGoalHandle; help(ServerGoalHandle)"
```

会打印：有哪些方法、每个方法**干什么**、**参数是什么**。

> `python3 -c "..."` = 让 Python **直接执行引号里这段代码**，不用建文件。

## 备查：动作 `goal_handle` 的常用成员

**注意：服务端和客户端的 `goal_handle` 是【两个不同的类】。**

| | 类名 | 常用成员 |
|---|---|---|
| **服务端**（动作服务端）| `ServerGoalHandle` | `.request`（读目标）<br>`.publish_feedback(msg)`（发反馈）<br>`.succeed()` / `.abort()` / `.canceled()`（表态）<br>`.is_cancel_requested`（客户端要取消吗）<br>`.goal_id` / `.status` |
| **客户端**（第 9 天的 `rotate_client`）| `ClientGoalHandle` | `.accepted`（被接受了吗）<br>`.get_result_async()`（去等结果）<br>`.cancel_goal_async()`（请求取消）|

**同名不同物，别搞混。**

## 还有哪些"运行时对象"会用到这个办法

| 对象 | 哪来的 | 你可能想查 |
|---|---|---|
| `goal_handle` | 动作回调的参数 | 上面那张表 |
| `future` | `call_async()` / `send_goal_async()` 返回 | `.result()` / `.done()` |
| `node`（`self`）| 你自己 | 所有 `self.create_xxx` 方法 |
| `msg` / `request` | 回调参数 | **这个用 `ros2 interface show`** ✅ |
