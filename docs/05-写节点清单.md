# 第一部分：写节点的顺序清单

**从上到下照着走，每一步打勾。**

## □ 第 1 步：三行 import

- [ ] `import rclpy`
- [ ] `from rclpy.node import Node`
- [ ] 从消息包里导入要用的类型（比如 `from geometry_msgs.msg import Twist`）

> 要导入什么类型？看你第 4 步决定了用什么。

---

## □ 第 2 步：定义类

- [ ] `class 类名(Node):` —— **必须继承 `Node`**
- [ ] 类名首字母大写

---

## □ 第 3 步：写 `__init__`（配置块，跑一次）

**逐个问自己：**

- [ ] **名字** → `super().__init__('节点名')`
- [ ] **要发数据吗？** → 是 → 建**发布者**
- [ ] **要收数据吗？** → 是 → 建**订阅者**
- [ ] **要定时做事吗？** → 是 → 建**定时器**
- [ ] 打个招呼 → `self.get_logger().info('...')`

>  **`__init__` 里不发任何消息** —— 这里只是"把工具准备好"。

---

## □ 第 4 步：写回调函数（干活块，反复跑）

** 两个致命细节：**

- [ ] **缩进 4 格**，和 `def __init__(self):` **左边对齐**（在类里面！）
- [ ] 如果是**订阅者**的回调，参数里要有 `msg`

**里面逐个问自己：**

- [ ] **要做什么？** → 造消息 / 读消息
- [ ] **填什么值 / 读什么字段？** → `msg.xxx = 值` 或 `读 msg.xxx`
- [ ] **要发出去吗？** → `self.发布者名.publish(msg)`

>  **定时器/订阅者里写回调函数名时，不要加括号！**
> `self.create_timer(0.1, self.回调名)` ← 没有 `()`

---

## □ 第 5 步：类外面的 `main()`（启动流程，跑一次）

** 缩进 0 格 —— 在类外面！**

- [ ] `rclpy.init()`
- [ ] `node = 类名()`
- [ ] `rclpy.spin(node)`
- [ ] `node.destroy_node()`
- [ ] `rclpy.shutdown()`

---

## □ 第 6 步：最后的调用

- [ ] `if __name__ == '__main__':`
- [ ] 下一行缩进 4 格：`main()`

---

## □ 第 7 步：注册到 `setup.py`

- [ ] 在 `entry_points` 的 `console_scripts` 里加一行：`'程序名 = 模块名.文件名:main',`
- [ ] **注意上一行末尾要有逗号**

## □ 第 8 步：编译运行

- [ ] **改了 setup.py → 必须先重编**：`cd ~/ros2_ws && colcon build --symlink-install`
- [ ] 只改了 `.py` 内容 → 不用重编
- [ ] 跑：`ros2 run 包名 程序名`

---

# 第二部分：语法形状（忘了怎么写的时候查这里）

**你只需要记"形状"，不用背整行。**

## 形状 1：起名字（在 `__init__` 里）

```
super().__init__('节点名')
```

## 形状 2：建发布者（要"发"数据时）

```
self.变量名 = self.create_publisher(
    消息类型,
    '话题名',
    10
)
```

## 形状 3：建订阅者（要"收"数据时）

```
self.变量名 = self.create_subscription(
    消息类型,
    '话题名',
    self.回调函数名,
    10
)
```

>  回调函数名**不加括号**
>  订阅者的回调函数，参数里要有 `msg`：
> ```
> def 回调名(self, msg):
> ```

## 形状 4：建定时器（要"定时"做事时）

```
self.变量名 = self.create_timer(
    间隔秒数,
    self.回调函数名
)
```

>  回调函数名**不加括号**

## 形状 5：造消息 + 填字段 + 发出去（在回调里）

```
msg = 消息类型()
msg.字段.子字段 = 值
self.发布者变量名.publish(msg)
```

>  **小数一定要写小数点**：`2.0` 不能写 `2`（否则 C 层断言失败，程序 Abort）

## 形状 6：读收到的消息（订阅者回调里）

```
def 回调名(self, msg):
    self.get_logger().info(f'收到: {msg.字段名}')
```

## 形状 7：主流程（固定不变）

```
def main():
    rclpy.init()
    node = 类名()
    rclpy.spin(node)
    node.destroy_node()
    rclpy.shutdown()


if __name__ == '__main__':
    main()
```

## 形状 8：建服务端（要"提供"服务时） 第 4 天补充

```
self.变量名 = self.create_service(
    服务类型,
    '服务名',
    self.回调函数名
)
```

>  **只有 3 个参数**（没有队列长度！）
>  回调函数名**不加括号**

## 形状 9：服务回调函数  第 4 天补充

```
def 回调名(self, request, response):
    # 读 request 里的字段（如果 srv 的请求部分是空的，就没得读）
    某变量 = request.字段名

    # 填 response 的字段
    response.字段1 = 值
    response.字段2 = 值

    return response          #  必须返回！不返回对方会一直卡着
```

>  **回调参数是两个**：`request` 和 `response`（订阅者只有一个 `msg`）
>  **必须 `return response`**

**导入服务类型的写法（注意是 `.srv`）：**

```
from 包名.srv import 服务名
```

例：`from std_srvs.srv import Trigger`

## 形状 10：声明参数（在 `__init__` 里） 第 6 天补充

```
self.declare_parameter('参数名', 默认值)
```

## 形状 11：读参数值  第 6 天补充

```
self.变量名 = self.get_parameter('参数名').value
```

>  **末尾的 `.value` 不能少** —— 少了它拿到的是"参数对象"，不是值。
>  **ROS 2 规定：不先 `declare` 就不能 `get`。**

## 形状 12：launch 文件骨架  第 7 天补充

```python
from launch import LaunchDescription
from launch_ros.actions import Node


def generate_launch_description():          #  函数名不能改
    return LaunchDescription([
        Node(
            package='包名',
            executable='程序名',              # setup.py entry_points 等号左边那个
            name='节点名',                    # 可选
            output='screen',                  # 把日志打到终端
        ),
        # 要几个节点写几个 Node(...)
    ])
```

## 形状 13：`Node(...)` 传参数  第 7 天补充

```python
Node(
    package='my_turtle',
    executable='draw_square',
    output='screen',
    parameters=[{'side_length': 3.0, 'turn_speed': 0.15}],   # ← Python 字典
)
```

>  **三种参数写法别混：**
> | 场景 | 格式 |
> |---|---|
> | 命令行 | `-p side_length:=3.0`（`:=`）|
> | launch 文件 | `{'side_length': 3.0}`（Python 字典）|
> | YAML 文件 | `side_length: 3.0`（YAML）|

## 形状 14：建服务**客户**端（在 `__init__` 里） 第 8 天补充

```
self.client = self.create_client(服务类型, '服务名')
```

> **只有 2 个参数** —— 没有回调函数！（客户端是主动方，自己发起自己等）

## 形状 15：发送请求并等响应  第 8 天补充

### 先看【放在哪】—— 这是骨架，比语法重要

```
class XxxClient(Node):
    def __init__(self):
        super().__init__('节点名')
        self.client = self.create_client(服务类型, '服务名')   # ← 形状 14
        #  __init__ 里【不发送】请求，只建客户端

    def send_request(self, value):        # ← 发送逻辑写成【单独的方法】
        # 形状 15 的五步写在这里
        ...


def main():
    rclpy.init()
    node = XxxClient()
    node.send_request(True)               # ← 在这里调用（传你要的参数）
    node.destroy_node()
    rclpy.shutdown()

# main() 里【没有 rclpy.spin(node)】—— 客户端不需要一直运行
```

**和发布者/订阅者的区别：**

| | 发布者/订阅者 | **客户端** |
|---|---|---|
| `__init__` 里 | 建发布者/订阅者 | **只建客户端** |
| 干活在哪 | **回调里**（被 ROS 2 调用）| **普通方法里**（你自己调用）|
| `main()` 里 | **必须有 `rclpy.spin`** | **不要 `spin`** |

> **为什么客户端不用 spin？** 因为它是"主动方" —— 发一次请求、等结果、结束。
> **不需要一直待命等别人调用。**

### 五步代码（写在上面那个方法里）

```
# ① 等服务端上线（不能省！否则后面会失败）
while not self.client.wait_for_service(timeout_sec=1.0):
    self.get_logger().info('等待服务...')

# ② 造请求 + 填字段
request = 服务类型.Request()
request.字段名 = 值

# ③ 发送（异步）
future = self.client.call_async(request)

# ④ 等响应回来
rclpy.spin_until_future_complete(self, future)

# ⑤ 取出响应
response = future.result()
self.get_logger().info(f'返回: {response.字段名}')
```

> **`future` 是"取餐号码牌"** —— 代表"还没到达的结果"。
> `call_async` 给你号码牌，`spin_until_future_complete` 等它做好，`result()` 取出结果。
>
>  **客户端的 `main()` 里不需要 `rclpy.spin(node)`** —— 发完请求拿到响应就可以退出了。

# 第三部分：命名规律（忘了方法名时推导）

| 你想干什么 | 英文动词 | 方法名 |
|---|---|---|
| 发东西 | publish | `create_publisher` |
| 收东西 | subscribe | `create_subscription` |
| 定时 | timer | `create_timer` |
| 记日志 | log | `get_logger` |
| 销毁节点 | destroy | `destroy_node` |
| 读参数 | parameter | `get_parameter` |
| 声明参数 | parameter | `declare_parameter` |

**规律：`create_xxx` = 建一个；`get_xxx` = 拿一个。**

**记不住拼写？用 VS Code 自动补全** —— 打 `self.create_` 按 `Ctrl+Space`，列表就出来了。

# 第四部分：三个最容易犯的错

| # | 错误 | 后果 |
|---|---|---|
| 1 | 回调函数**没缩进到类里** | `AttributeError: ... has no attribute` |
| 2 | 存取变量名**不一致**（存 `publishers` 用 `publisher_`）| `AttributeError` |
| 3 | 浮点字段写了**整数**（`2` 而不是 `2.0`）| **C 层断言失败，程序 Aborted** |

# 第五部分：命名规范 （第 4 天补充）

## 各种名字的大小写规则

| 什么东西 | 规则 | 例子 | 对照 |
|---|---|---|---|
| **Python 类名** | **首字母大写**（大驼峰）| `TurtleCircler` `PoseReader` `PubSub` | ✅ |
| **ROS 包名** | 全小写 + 下划线 | `my_turtle` `nav2_bringup` | ✅ |
| **ROS 节点名** | 全小写 + 下划线 | `turtle_circler` `pub_sub` | ✅ |
| **话题名** | 全小写 + 下划线 + 用 `/` 分层 | `/turtle1/cmd_vel` | ✅ |
| **Python 文件名** | 全小写 + 下划线 | `draw_circle.py` | ✅ |
| **Python 函数/变量** | 全小写 + 下划线 | `read_pose` `cmd` | ✅ |

### 一句话记住

> **只有【类名】首字母大写，其他全部小写 + 下划线。**

| 写法 | 对不对 |
|---|---|
| `class PoseReader(Node):` | ✅ |
| `class pose_reader(Node):` | ❌ 类名该大写 |
| `super().__init__('pose_reader')` | ✅ 节点名小写 |
| `super().__init__('PoseReader')` | ❌ 节点名不该大写 |
| `self.create_publisher(...)` | ✅ 方法名小写 |
| `/turtle1/cmd_vel` | ✅ 话题名小写 |

## 节点的"三个名字"，不需要一样

一个节点其实有**三个**相关的名字，**可以不同**：

| 名字 | 写在 | 例子 | 作用 |
|---|---|---|---|
| **文件名** | 磁盘上的 `.py` | `wall_stopper.py` | Python 找文件用 |
| **程序名** | `setup.py` 的 `entry_points` | `wall_stopper` | `ros2 run` 时用 |
| **节点名** | `super().__init__('...')` | `pub_sub` | `ros2 node list` 里显示 |

**你的 `PubSub` 就是这样：文件名可能叫 `wall_stopper.py`，程序名 `wall_stopper`，但节点名是 `pub_sub`。**

**三个名字可以完全不同，互不影响。**

> **建议**：初学阶段**三个保持一致**，少一个记忆负担。
> 等熟了再根据需要区分（比如一个文件里放多个程序时，就必须区分了）。

## 话题名的"/"开头是什么意思

| 写法 | 叫法 | 含义 |
|---|---|---|
| `/turtle1/cmd_vel` | **绝对名称** | 从根开始，不受命名空间影响 ✅ **推荐** |
| `turtle1/cmd_vel` | **相对名称** | 相对于节点所在命名空间 |

**不加 `/` 也能跑**（因为你的节点在根命名空间下），
**但加了更安全** —— 以后把节点放进命名空间（多机器人场景）时会出问题。

**建议：写话题名时一律加开头的 `/`。**

# 第六部分：什么时候要重新编译

| 改了什么 | 重编？ |
|---|---|
| 已注册文件（`.py` / launch / config）的**内容** | ❌ 不用 |
| **新增文件**并注册到 `setup.py` | ✅ **要** |
| **`setup.py`（尤其是 entry_points / data_files）** | ✅ **要** |
| `package.xml` | ✅ 要 |
| **不确定** | **✅ 重编，反正几秒钟** |

**一句话：改【内容】不用重编；改【结构】要重编。**

> **为什么？** `--symlink-install` 让已存在的文件用**符号链接**指向源码 ——
> 改源码内容，链接那边立刻是新的。**但新增文件需要建立新链接 → 必须重编。**

# 第七部分：怎么知道一个类型有哪些字段

> **这是最常问的问题：`request` / `response` / `msg` 后面能接什么？**

## 方法 1：查类型定义（最权威）

```bash
ros2 interface show <完整类型名>
```

**例：**
```bash
ros2 interface show std_srvs/srv/SetBool
```

**输出：**
```
bool data
---
bool success
string message
```

## 方法 2：VS Code 自动补全（最快）

**在代码里打 `request.` 或 `response.` 或 `msg.`，等补全列表弹出来。**

## 方法 3：列出所有类型

```bash
ros2 interface list | grep "/srv/"      # 所有服务类型
ros2 interface list | grep "/msg/"      # 所有消息类型
ros2 interface package <包名>            # 某个包定义了哪些
```

---

## 从类型定义 → 代码里的字段名（关键映射）

**规则：类型定义里的【每一行】= 一个字段。字段名就是"类型后面那个词"。**

### 例子 1：`msg` 类型（消息）

```bash
ros2 interface show turtlesim/msg/Pose
```
```
float32 x
float32 y
float32 theta
float32 linear_velocity
float32 angular_velocity
```

**代码里就能用：**
```python
msg.x          msg.y         msg.theta
msg.linear_velocity          msg.angular_velocity
```

### 例子 2：`srv` 类型（服务）—— 注意中间的分隔线

```bash
ros2 interface show std_srvs/srv/SetBool
```
```
bool data
---
bool success
string message
```

| 位置 | 内容 | 代码里怎么用 |
|---|---|---|
| `---` **上面** | `bool data` | **请求** → `request.data` |
| `---` **下面** | `bool success`<br>`string message` | **响应** → `response.success`<br>`response.message` |

### 例子 3：`Empty` 类型（空的）

```bash
ros2 interface show std_srvs/srv/Empty
```
**输出：什么都没有。**

**所以：** 没有 `request.xxx` 可读，也没有 `response.xxx` 可填。
**回调里什么都不用填，但 `return response` 还是要写。**

### 例子 4：`Trigger` 类型

```bash
ros2 interface show std_srvs/srv/Trigger
```
```
---
bool success
string message
```

| 位置 | 内容 | 代码里 |
|---|---|---|
| `---` 上面 | （空）| **请求没字段可读** |
| `---` 下面 | `success`、`message` | `response.success`、`response.message` |

---

## 一句话记忆

> **想知道 `request` / `response` / `msg` 能接什么 → 跑一次 `ros2 interface show <类型>`。**
>
> **`---` 上面给 `request`，下面给 `response`；消息（msg）没有分隔线，全部给 `msg`。**

## 连带的：怎么知道自己该用哪个类型

```bash
# 看某个话题用的是什么类型
ros2 topic list -t

# 看某个节点发布了/订阅了什么类型
ros2 node info /节点名

# 看某个服务用的是什么类型
ros2 service type /服务名
```
