## 最常用的 6 条（先记这些）

```bash
# ① 启动乌龟窗口（虚拟机桌面终端里跑）
ros2 run turtlesim turtlesim_node

# ② 键盘遥控乌龟
ros2 run turtlesim turtle_teleop_key

# ③ 看现在有哪些节点
ros2 node list

# ④ 看现在有哪些话题
ros2 topic list

# ⑤ 编译你的代码（注意 --packages-select）
cd ~/ros2_ws && colcon build --packages-select my_turtle --symlink-install

# ⑥ 运行你自己写的程序
ros2 run my_turtle draw_circle
```

> ⚠️ **编译命令别用错**（第 11 天踩过的坑）：
>
> | 场景 | 命令 |
> |---|---|
> | 日常（改 `my_turtle`）| `colcon build --packages-select my_turtle --symlink-install` |
> | **改接口**（`my_interfaces`）| `colcon build --packages-select my_interfaces` ← **不加** `--symlink-install` |
> | **改机器人模型 / 世界文件**（`my_robot_description`，CMake 资源包）| `colcon build --packages-select my_robot_description` ← **不加** `--symlink-install`，**但改完内容必须重编** |
> | 全量 | `colcon build` |
>
> **判断开关**：这次编译**会不会碰到 `my_interfaces` 或别的 CMake 包**。
> 原因见 `08-踩坑总集.md` **坑 47**；完整规则见本文件 **§2.5 第 5 步：编译**（「什么时候要重编」+「常用编译选项」）。

## 1.1 常见类型的字段速查

| 类型 | 字段 | 怎么用 |
|---|---|---|
| `geometry_msgs/msg/Twist` | `linear.x` `linear.y` `linear.z`<br>`angular.x` `angular.y` `angular.z` | 发速度：`msg.linear.x = 2.0` |
| `turtlesim/msg/Pose` | `x` `y` `theta`<br>`linear_velocity` `angular_velocity` | 读位置：`msg.x` |
| `std_srvs/srv/SetBool` | 请求：`data`<br>响应：`success` `message` | `request.data`<br>`response.success = True` |
| `std_srvs/srv/Trigger` | 请求：（空）<br>响应：`success` `message` | `response.message = '...'` |
| `std_srvs/srv/Empty` | 请求：（空）<br>响应：（空） | **没有 `request.xxx` 可读、也没有 `response.xxx` 可填**，但 `return response` 还是要写 |

**查任何类型的方法：**
```bash
ros2 interface show <完整类型名>
```

## 2.5 第 5 步：编译

```bash
cd ~/ros2_ws                     #  必须在工作空间【根目录】
colcon build --packages-select <包名> --symlink-install
```

**预期输出**：`Summary: 1 package finished`

> ⚠️ **为什么要加 `--packages-select`**（第 11 天踩的坑）：
> 工作空间里一旦有**接口包**（如 `my_interfaces`），
> **全量的 `colcon build --symlink-install` 会直接报错**：
> `existing path cannot be removed: Is a directory`。
>
> | 编什么 | 命令 |
> |---|---|
> | Python 包（`my_turtle`）| `--packages-select my_turtle --symlink-install` |
> | **接口包**（`my_interfaces`）| `--packages-select my_interfaces` ← **不加 flag** |
> | **CMake 资源包**（`my_robot_description`：urdf / launch / config / worlds）| `--packages-select my_robot_description` ← **不加 flag** |
> | 全量 | `colcon build` |
>
> 详见 `08-踩坑总集.md` **坑 47**。

### 什么时候要重编（★ 按【包类型】分，结论不一样）

| 改了什么 | Python 包<br>（`ament_python` + `--symlink-install`）| CMake 资源包<br>（`my_robot_description` 等 `ament_cmake`）|
|---|---|---|
| **已注册文件的【内容】**<br>（`.py`、launch、config、`urdf`、`worlds` 都算）| ❌ **不用**（软链指向源码）| ✅ **必须要**（`install/` 里是**拷贝**）|
| **新增文件**并注册到 `setup.py` / `CMakeLists.txt` | ✅ **要** | ✅ **要** |
| **`setup.py` 本身**（entry_points / data_files）| ✅ **要** | —（没有 `setup.py`）|
| **`CMakeLists.txt` 本身** | — | ✅ **要** |
| **`package.xml`** | ✅ 要 | ✅ 要 |
| **不确定** | ✅ **重编，几秒钟的事** | ✅ **重编，几秒钟的事** |

> ⚠️ **别把第一行记混了** —— `my_robot_description` 是 **`ament_cmake`** 包，
> 它的 `install/share/...` 是**拷贝**：**改了 URDF / launch / config / 世界文件，不重编就永远不会生效**
> （表现为反复"改了没生效"，见 `10-原理与排查方法.md` §4.3）。
>
> **只有 Python 包 + `--symlink-install` 才享受"改内容不用重编"这个待遇。**

**为什么 Python 包不用重编？**

> `--symlink-install` 让"已存在的文件"用**符号链接**指向源码 ——
> 所以你改源码内容，链接那边立刻就是新的。
> **但"新增文件"需要建立新的链接 → 必须重编。**
> **而 CMake 包没有这个待遇 —— 它是实打实的拷贝。**
>
> **实测验证**（第 7 天，Python 包 `my_turtle`）：改了 `square_demo.launch.py` 的**内容**（加 `parameters=`），
> **没重编直接跑，生效了** ✅

### 常用编译选项

| 选项 | 作用 |
|---|---|
| `--symlink-install` | 符号链接代替复制（**Python 包必加**）|
| `--packages-select <包名>` | 只编译指定的包 |
| `--cmake-clean-cache` | 清了重编（疑难杂症时用）|

### 验证资源文件装进去了没

```bash
ls ~/ros2_ws/install/<包名>/share/<包名>/config/
```

> **注册过 `data_files` 才看得到这里的内容**（launch 文件同理，在 `share/<包名>/launch/`）。
> 目录空的 = `setup.py` 没改对，或者改了没重编。
> **`setup.py` 该改哪一行见 `05-写节点清单.md` 第一部分第 7 步 ②。**

# 第三部分（§3）：命令分类速查

## 3.1 命令的通用结构

**ROS 2 的命令几乎都是这个形状：**

```
ros2  <类别>  <动作>  [参数...]
       └─┬─┘  └─┬─┘
     操作什么   怎么操作
```

**举例：**

| 命令 | 类别 | 动作 |
|---|---|---|
| `ros2 node list` | node（节点）| list（列出）|
| `ros2 topic echo /turtle1/pose` | topic（话题）| echo（打印内容）|
| `ros2 service call ...` | service（服务）| call（调用）|
| `ros2 pkg executables turtlesim` | pkg（包）| executables（列出程序）|

**记住这个结构，你就能"猜"出命令。**

> **忘了有什么动作？** 只敲类别，它会列出所有可选动作：
> ```bash
> ros2 topic          # 回车，列出 topic 下所有动作
> ros2 node --help    # 看详细帮助
> ```

---

## 3.2 启动类命令（天天用）

### 启动任意一个程序

```bash
ros2 run <包名> <程序名>
         └──┬─┘ └──┬──┘
        哪个包   包里的哪个程序
```

| 例子 | 干什么 |
|---|---|
| `ros2 run turtlesim turtlesim_node` | **启动乌龟窗口** |
| `ros2 run turtlesim turtle_teleop_key` | 键盘遥控乌龟 |
| `ros2 run turtlesim draw_square` | 官方的画正方形程序 |
| `ros2 run my_turtle draw_circle` | **你自己写的转圈节点** |
| `ros2 run my_turtle read_pose` | 你自己写的读位置节点 |

>  **`turtlesim_node` 有图形界面，必须在【虚拟机桌面终端】跑**
> VS Code 的 SSH 终端没有显示环境，会报 `cannot open display`。
> 纯计算的节点（如 `draw_circle`）没这个限制。

### 用 launch 文件启动（一次起多个节点 + 传参）

```bash
ros2 launch <包名> <launch文件名>
```

**一次启动一整个场景**（节点 + 参数 + 顺序），比开好几个终端 `ros2 run` 省事。

**实例（都是你自己写的）：**

```bash

ros2 launch my_turtle circle_demo.launch.py     # 第 10 天：带 circle_params.yaml 参数
ros2 launch my_turtle polygon_demo.launch.py    # 第 13 天：一次起 3 个节点
ros2 launch my_robot_description gazebo.launch.py   # 第 19–24 天：一条命令起【整套仿真】
```

> **最后那条是"一条命令起全套"** —— 它一次拉起 `gz sim`（server + gui）、`robot_state_publisher`、
> `ros_gz_sim create`、`ros_gz_bridge` 四个东西。**命令细节见 §3.11「Gazebo / ros_gz 命令」。**

> **launch 文件名必须是【完整文件名】**（含 `.launch.py`），和 `ros2 run` 只写程序名不一样。
>
> **前提**：launch 文件要先在 `setup.py` 的 `data_files` 里**注册**，再**重编 + `source`**
> —— **没注册就 `ros2 launch` 看不见它**（见 `05-写节点清单.md` 第一部分第 7 步 ②）。

### 查看

```bash
ros2 service list               # 列出所有服务
ros2 service list -t            # 连带显示服务类型
ros2 service type /服务名        # 查某个服务是什么类型
ros2 service list | grep 关键词   # 筛选（找自己的服务）
```

### 查有哪些服务类型可用

```bash
ros2 interface list | grep "/srv/"        # 列出所有服务类型
ros2 interface show std_srvs/srv/SetBool  # 看某个类型长什么样
```

### 调用服务

```bash
ros2 service call <服务名> <服务类型> "<请求内容>"
         └──┬──┘ └──┬──┘ └───┬───┘ └────┬────┘
          命令   调用   哪个服务   它的类型    请求内容
```

| 类型 | 请求内容怎么写 |
|---|---|
| `std_srvs/srv/Empty`（请求是空的）| **不用写**，命令到此结束 |
| `std_srvs/srv/SetBool` | `"{data: true}"` 或 `"{data: false}"` |
| `std_srvs/srv/Trigger`（请求是空的）| **不用写** |
| `turtlesim/srv/Spawn` | `"{x: 8.0, y: 8.0, theta: 0.0, name: 'xx'}"` |

>  **命令行里的布尔值写小写 `true` / `false`**（YAML 写法），
> **Python 代码里写大写 `True` / `False`**。

### 常用服务调用实例

```bash
# 清屏（Empty 类型 —— 不需要请求内容）

# 生成新乌龟
ros2 service call /spawn turtlesim/srv/Spawn "{x: 8.0, y: 8.0, theta: 0.0, name: 'myturtle'}"

# 乌龟瞬移
ros2 service call /turtle1/teleport_absolute turtlesim/srv/TeleportAbsolute "{x: 2.0, y: 2.0, theta: 0.0}"

# 调用自己写的服务（第 5 天的 turtle_control）
ros2 service call /movemove std_srvs/srv/SetBool "{data: true}"    # 让乌龟走
ros2 service call /movemove std_srvs/srv/SetBool "{data: false}"   # 让乌龟停

# 调用自己写的服务（第 4 天的 greeter）
ros2 service call /say_hello std_srvs/srv/Trigger
```

### 完整实战流程（调用自己写的服务）

```bash
ros2 run turtlesim turtlesim_node                                    # 终端 A：先起乌龟窗口
ros2 run my_turtle turtle_control                                    # 终端 B：起你的节点
ros2 service list | grep movemove                                    # 终端 C：确认注册了（预期 /movemove）
ros2 service call /movemove std_srvs/srv/SetBool "{data: true}"      # 调用 → 乌龟开始走
ros2 service call /movemove std_srvs/srv/SetBool "{data: false}"     # 反向调用 → 乌龟停下
```

> **顺序就四件事**：**先起被调用的节点 → 确认服务出现在列表里 → 再 `service call`**。
> **每个程序占一个终端**；`service call` 一问一答，发完就结束。

### 三个标准服务类型速查

> **字段全貌见 §1.1「常见类型的字段速查」** —— 那里是唯一写全的一份，本处不再抄第二份。

| 类型 | 请求字段 | 响应字段 | 用在 |
|---|---|---|---|
| `std_srvs/srv/Empty` | （空）| （空）| 只要触发，不要参数也不要结果 |
| **`Trigger`** | 字段见 §1.1 | 字段见 §1.1 | 触发 + 要结果 |
| **`SetBool`** | 字段见 §1.1 | 字段见 §1.1 | 设置一个开关 |

### 动作 (Action)  第 9 天补充

> **动作 = 服务（目标/结果）+ 话题（反馈）+ 状态管理（可取消）**
> 适合**长任务**：能实时看进度、能中途取消。

### 查看

```bash
ros2 action list                      # 列出所有动作
ros2 action list -t                   # 连带显示动作类型
ros2 action info /动作名               # 谁在提供、谁在调用
ros2 interface show <动作类型>         # 看格式
ros2 interface list | grep "/action/" # 列出所有动作类型
```

**实例：**
```bash
ros2 action list -t
# 预期：/turtle1/rotate_absolute [turtlesim/action/RotateAbsolute]

ros2 interface show turtlesim/action/RotateAbsolute
# 预期：float32 theta / --- / float32 delta / --- / float32 remaining
#（三段含义见下面「动作文件的格式」，本处不再标注第二遍）
```

### 调用动作（命令行）

```bash
ros2 action send_goal <动作名> <动作类型> "<目标内容>" --feedback
```

| 部分 | 含义 |
|---|---|
| `send_goal` | 发送目标（不是 `call`！）|
| `--feedback` | **加它才能看到实时反馈** |

**实例：**
```bash
ros2 action send_goal /turtle1/rotate_absolute turtlesim/action/RotateAbsolute "{theta: 1.5708}" --feedback
```

**预期：**
| 现象 | 说明 |
|---|---|
| 乌龟转动到 90° | 目标执行中 |
| 终端持续打印 `feedback: remaining=...` | **实时反馈**（数值递减）|
| 最后打印 `result: delta=...` | 完成，返回结果 |

### 动作文件的格式（两条 `---` 分三段）

```
float32 theta        ← 目标 goal      （第一条 --- 上面）
---
float32 delta        ← 结果 result    （两条 --- 之间）
---
float32 remaining    ← 反馈 feedback  （第二条 --- 下面）
```

>  **顺序是：目标 → 结果 → 反馈**（不是"目标→反馈→结果"）
> **对比 `srv`：只有一条 `---`，两段（请求 / 响应）。**

### 三种通信机制速查

| | 话题 Topic | 服务 Service | **动作 Action** |
|---|---|---|---|
| 模式 | 发布/订阅 | 请求/响应 | 目标/反馈/结果 |
| 时长 | 持续 | 短 | **长任务** |
| 看进度 | — | ❌ | ✅ |
| 可取消 | — | ❌ | ✅ |
| 类比 | 广播电台 | 打电话 | **点外卖** |
| 命令行 | `topic pub` | `service call` | **`action send_goal`** |

```bash
ros2 interface list                          # 列出所有消息/服务/动作类型
ros2 interface list | grep "/msg/"           # 只看消息类型
ros2 interface show <完整类型名>              # 看某个类型长什么样
ros2 interface package <包名>                 # 看某个包定义了哪些接口
```

**示例：**

```bash

ros2 interface show turtlesim/msg/Pose
ros2 interface show turtlesim/srv/Spawn
ros2 interface show std_srvs/srv/Empty
```

#### 怎么知道一个类型有哪些字段（从 `05` 第七部分迁来）

> **这是最常问的问题：`request` / `response` / `msg` 后面能接什么？**

**三个办法：**

| 办法 | 怎么做 | 什么时候用 |
|---|---|---|
| **① 查类型定义（最权威）** | `ros2 interface show <完整类型名>` | 想确认字段名 |
| **② VS Code 自动补全（最快）** | 代码里打 `request.` / `response.` / `msg.`，等列表弹出 | 写代码时 |
| **③ 列出所有类型** | `ros2 interface list \| grep "/srv/"`、`ros2 interface package <包名>` | 忘了类型名 |

**从类型定义 → 代码里的字段名（关键映射）**

**规则：类型定义里的【每一行】= 一个字段。字段名就是"类型后面那个词"。**

**例 1：`msg` 类型（消息）—— 没有分隔线，全部给 `msg`**

```bash
ros2 interface show turtlesim/msg/Pose
```

```
float32 x
float32 y
float32 theta
float32 linear_velocity
float32 angular_velocity
```

代码里就能用：`msg.x` `msg.y` `msg.theta` `msg.linear_velocity` `msg.angular_velocity`

**例 2：`srv` / `action` 类型 —— 注意中间的分隔线**

| 分隔线 | 给谁 |
|---|---|
| **第一条 `---` 上面** | **`request`**（请求）|
| **第一条 `---` 下面** | **`response`**（响应）—— `srv` 到此为止 |
| **第二条 `---` 下面**（只有 `action` 有）| **`feedback`**（反馈）|

> **`SetBool` / `Trigger` / `Empty` / `Twist` 这几个常用类型的字段，全貌统一见 §1.1
> 「常见类型的字段速查」** —— 那里是唯一写全的一份，本处不再抄第二份。

**一句话记忆：**

> **想知道 `request` / `response` / `msg` 能接什么 → 跑一次 `ros2 interface show <类型>`。**
> **`---` 上面给 `request`，下面给 `response`；消息（msg）没有分隔线，全部给 `msg`。**

**连带的：怎么知道自己该用哪个类型**

```bash
# 看某个话题用的是什么类型
ros2 topic list -t

# 看某个节点发布了/订阅了什么类型
ros2 node info /节点名

# 看某个服务用的是什么类型
ros2 service type /服务名
```

> **写代码时怎么用这些字段**（造消息 / 填字段 / 读字段）见 `05-写节点清单.md` **形状 5、6、9**。

## 3.5 几条相似的命令，对照记

**它们结构一样，只是"发什么"不同：**

```bash
ros2 run            <包名> <程序名>
ros2 topic pub      <话题名> <消息类型> "<内容>"
ros2 service call   <服务名> <服务类型> "<请求内容>"
ros2 action send_goal <动作名> <动作类型> "<目标内容>" [--feedback]
```

| 命令 | 通信方式 | 特点 |
|---|---|---|
| `ros2 run` | 启动一个程序 | 启动后一直运行 |
| `ros2 topic pub` | **发布**（单向广播）| 一直发（除非 `--once`）|
| `ros2 service call` | **调用**（一问一答）| **发一次，等回复，结束** |
| `ros2 action send_goal` | **发目标**（长任务）| **能看反馈（`--feedback`）、能取消** |

**记忆锚点：**

> **`pub` = 广播，发完就走**
> **`call` = 打电话，等对方回复**
> **`send_goal` = 点外卖，能看骑手到哪了、能取消**

### 三个"查看类型"的命令也平行

> **这一组在 §3.3 已经列全**（`topic / service / action list -t`、`interface list | grep "/msg/"` 等）
> —— **本处不再抄第二份。**

## 3.6 类型名的三段式写法

| 类型 | 格式 | 例子 |
|---|---|---|
| 消息 | `包名/msg/消息名` | `geometry_msgs/msg/Twist` |
| **服务** | `包名/srv/服务名` | `turtlesim/srv/Spawn` |
| 动作 | `包名/action/动作名` | `nav2_msgs/action/NavigateToPose` |

** 常见错误：**

| 写错 | 写对 |
|---|---|
| `geometry_msgs.msg.Twist`（在命令行里）| `geometry_msgs/msg/Twist` |
| — | （`from geometry_msgs.msg import Twist` 里才用点）|

**命令行里用斜杠 `/`，Python 代码里用点 `.`。**

### 命令类报错

| 报错 | 原因 | 解决 |
|---|---|---|
| `Package 'xxx' not found` | 终端没 source 工作空间 | `source ~/ros2_ws/install/setup.bash` |

### Python 报错

| 报错 | 原因 | 解决 |
|---|---|---|
| `AttributeError: 'Greeter' object has no attribute 'operation'` | **回调函数没缩进到类里**，或类里没这个方法 | 检查缩进；用 VS Code 折叠功能验证 |
| `AttributeError: ... has no attribute 'publisher_'` | **存的名字和用的名字不一致** | 存 `self.publisher_` 就得用 `self.publisher_` |
| `AttributeError: ... has no attribute 'messsage'` | **字段名拼写错误** | 用 VS Code 自动补全（打 `response.` 看列表）|
| **`UnboundLocalError: ... local variable 'xxx'`** | **忘了写 `self.`** | 引用自己类里方法/属性必须加 `self.` |
| `NameError: name 'xxx' is not defined` | 用了没导入的名字 | 检查文件开头的 import |
| `TypeError: ... takes N positional arguments` | 函数参数个数不对 | 对照形状模板数参数 |
| `IndentationError` | 缩进不对 | 同类方法左边对齐（缩进 4 格）|
| **`Assertion 'PyFloat_Check' failed` + `Aborted`** | **浮点字段赋了整数** | `2` → `2.0`，`0` → `0.0` |

|---|---|---|
| **`Scene already exists with name: scene`** + **`Segmentation fault`** | **`Sensors` 插件在【世界文件】和【URDF】里写了两遍** —— 两个渲染线程抢着建 `scene` | **只保留一处**（我们留 URDF 里的）；见坑 77 |

## 3.10 QoS —— 消息的"投递服务等级"（第 23 天补充）

> **QoS 不决定"送什么"，决定"怎么送、送到什么程度"。**
> **它【按话题】设；发布者和订阅者两边必须【兼容】—— 不兼容的表现是【静默收不到，也不报错】。**

### 四个核心项

| QoS 项 | 取值 | 意思 |
|---|---|---|
| **Reliability**（可靠性）| **`reliable`** / **`best_effort`** | `reliable`：**保证送到**（丢包会重传）<br>`best_effort`：**尽力而为**（丢了不重传，但延迟低）|
| **Durability**（持久性）| **`volatile`** / **`transient_local`** | `volatile`：**只给"此刻在听的人"**<br>`transient_local`：**后来订阅的人也补发最后几条**（= 常说的 "latched"）|
| **History** | `keep_last` / `keep_all` | 队列保留**最新 N 条**，还是**全部** |
| **Depth** | 数字 | 队列长度（`keep_last` 时保留几条）|

### 为什么需要它：不同数据的"容忍度"完全不同

| 数据 | 能丢吗 | 能延迟吗 | 后订阅的要不要补 | → 该用什么 |
|---|---|---|---|---|
| **图像 / 激光** | ✅ **丢一帧没事** | ❌ **绝不能延迟** | ❌ 不用 | **`best_effort` + `volatile`** |
| **速度指令 `/cmd_vel`** | ❌ **绝不能丢** | 稍微能忍 | ❌ 不用 | **`reliable` + `volatile`** |
| **`/robot_description`** | ❌ 不能丢 | ✅ 无所谓 | ✅ **必须要** | **`reliable` + `transient_local`** |
| **`/tf_static`** | ❌ 不能丢 | ✅ 无所谓 | ✅ **必须要** | **`reliable` + `transient_local`** |
| **`/tf`** | ❌ 不能丢 | ❌ 高频 | ❌ **绝不能缓存** | **`reliable` + `volatile`** |

> **最后两行就是"为什么 `/tf_static` 要单独一个话题"的答案** ——
> **为什么必须拆、合并会怎样，完整推导见 `10-原理与排查方法.md` §3.3**（本处只留这张表）。

### 兼容性（⭐ 最容易坑人的地方）

| 发布者 | 订阅者 | 兼容？ |
|---|---|---|
| `reliable` | `best_effort` | ✅ 可以 |
| **`best_effort`** | **`reliable`** | ❌ **不兼容** |
| `transient_local` | `volatile` | ✅ 能连上，**但拿不到历史** |
| **`volatile`** | **`transient_local`** | ❌ **不兼容** |

> ## **口诀：收的人要求不能比发的人更高。**
> **不兼容的表现 = 两边都"正常跑着"，但【收不到数据，也不报错】** ——
> **和"话题没人发"是同一族现象**（见 `08` 坑 48 / 69 / 70 / 71）。

### 查 QoS

```bash
ros2 topic info /话题名              # 简单版：谁在发、谁在收（只给数字）
ros2 topic info /话题名 --verbose     # ★ 详细版：两边的 QoS 全部列出来
```

**要会看这三处**：

```
Publisher count: 1          ← 有发布者吗？（0 = 没人发）
Subscription count: 0       ← ★ 0 = 根本没连上，不是"连上了没数据"
QoS profile:
  Reliability: BEST_EFFORT
  Durability: VOLATILE
```

> **`Subscription count: 0` 是个关键信号** ——
> **说明"没订阅上"（可能 QoS 不兼容），而不是"订阅上了但没数据"。**

**`ros2 topic echo` 收不到数据时，通常是 QoS 不匹配**：

```bash
ros2 topic echo /scan --qos-reliability best_effort
ros2 topic echo /robot_description --qos-durability transient_local --once
```

### 默认值（不写 QoS 时用哪个）

| 场合 | 默认 QoS |
|---|---|
| **普通话题** | `reliable` + `volatile` + `keep_last(10)` |
| **传感器（`SensorDataQoS`）** | `best_effort` + `volatile` + `keep_last(5)` |
| **系统默认（`SystemDefaultsQoS`）** | `reliable` + `volatile` |

### 代码里怎么写

```python
from rclpy.qos import QoSProfile, ReliabilityPolicy, DurabilityPolicy

qos = QoSProfile(
    depth=10,
    reliability=ReliabilityPolicy.RELIABLE,
    durability=DurabilityPolicy.TRANSIENT_LOCAL,
)

# ★ 这是 create_xxx 的【第 4 个参数】—— 订阅、发布都有
self.pub = self.create_publisher(String, 'my_topic', qos)
self.sub = self.create_subscription(String, 'my_topic', self.cb, qos)
```

> ⚠️ **服务没有 QoS 参数** —— 别把队列长度带过去（**坑 68**）。

## 3.11 Gazebo / ros_gz 命令（第 19–24 天补充）

> **这一节收"仿真时每天在敲"的命令。**
> **§3.1–§3.10 都是 ROS 2 自己的命令；Gazebo 是另一套软件**（它说 gz-transport 的语言）——
> 所以命令是两族：**ROS 2 那边 `ros2 ...`，Gazebo 那边 `gz ...`。**
>
> **"谁在发、谁在收、为什么必须有 bridge"的原理，见 `10-原理与排查方法.md` §1。**

### 一条命令起全套（最常用）

```bash
ros2 launch my_robot_description gazebo.launch.py
```

**它一次拉起四个东西**，这就是"仿真全套"：

| 拉起了什么 | 是什么 |
|---|---|
| `gz sim` | Gazebo 本体 —— **其实 fork 出 server + gui 两个进程** |
| `robot_state_publisher` | ROS 2 节点：URDF + `/joint_states` → TF |
| `ros_gz_sim create` | ROS 2 节点：把机器人塞进世界，**跑一下就退出** |
| `ros_gz_bridge` | ROS 2 节点：ROS 2 ↔ Gazebo 消息互译 |

> ⚠️ **`my_robot_description` 是【CMake 资源包】** ——
> **改了 launch / URDF / config / 世界文件，必须重编**：
> `colcon build --packages-select my_robot_description`（**不加 flag**）——
> 否则就是反复"改了没生效"（完整规则见 §2.5，现象见 `10-原理与排查方法.md` §4.3）。

### 起桥：`ros_gz_bridge`

**没有桥，两边是两个世界** —— ROS 2 看不见 gz 话题，gz 也看不见 ROS 2 话题。

```bash
# ① 用配置文件（我们的做法）
ros2 run ros_gz_bridge parameter_bridge --ros-args -p config_file:=<配置文件的绝对路径>

# ② 一条一条写在命令行上（格式：ROS话题@ROS类型@gz类型）
ros2 run ros_gz_bridge parameter_bridge /cmd_vel@geometry_msgs/msg/Twist@gz.msgs.Twist
```

| 部分 | 含义 |
|---|---|
| `parameter_bridge` | bridge 这个"程序"的名字 |
| `--ros-args -p config_file:=...` | **把 YAML 配置当参数传进去**（注意是 `:=`，不是 `=`）|
| `/cmd_vel@geometry_msgs/msg/Twist@gz.msgs.Twist` | 话题名 + ROS 类型 + gz 类型，**用 `@` 连起来** |

**配置 YAML 长这样**（`direction` 决定"往哪边翻"）：

```yaml
- ros_topic_name: "/cmd_vel"
  gz_topic_name: "/cmd_vel"
  ros_type_name: "geometry_msgs/msg/Twist"
  gz_type_name: "gz.msgs.Twist"
  direction: ROS_TO_GZ          # ROS 2 → Gazebo
- ros_topic_name: "/odom"
  gz_topic_name: "/odom"
  ros_type_name: "nav_msgs/msg/Odometry"
  gz_type_name: "gz.msgs.Odometry"
  direction: GZ_TO_ROS          # Gazebo → ROS 2
```

> **两个方向的含义见 `10-原理与排查方法.md` §1.4。**
> ⚠️ **类型名两边写法不一样**：**ROS 2 用 `/` 分三段**（`geometry_msgs/msg/Twist`），
> **gz 用 `.` 分两段**（`gz.msgs.Twist`）—— **写反了 bridge 起不来**。

### 造模型：`ros_gz_sim create`

```bash
# 从文件读（不依赖任何节点）
ros2 run ros_gz_sim create -file <模型文件.sdf> -name my_robot -x 3 -y 0 -z 0.5

# 从话题读（需要 robot_state_publisher 在跑）
ros2 run ros_gz_sim create -topic /robot_description -name my_robot -z 0.5
```

| 参数 | 意思 |
|---|---|
| `-file <文件>` | 模型定义**直接从文件读** —— 不依赖任何节点 |
| `-topic <话题>` | 模型定义**从话题读** —— ★ **需要 `robot_state_publisher` 在跑** |
| `-name <名字>` | 放进世界后叫什么 |
| `-x -y -z` | **放在哪** —— ★ **它会【覆盖】SDF 文件里写的 `<pose>`** |
| `-z 0.5` | 抬高半米，别一开始就陷进地面 |

> ⚠️ **位置写在【命令】上，不写在 SDF 里** —— 改了 SDF 的 `<pose>` 却"还在原点"，
> 就是因为 `-x -y -z` 把它覆盖了（**坑 75**）。**不写 `-x -y -z` = 默认 `0 0 0`**，模型和原点重合。
>
> ⚠️ **报 `Entity creation successful` ≠ 模型真的在世界里** —— 那只说明"服务调通了"。
> **必须用下面的 `gz model --list` 验证**（**坑 71**）。
>
> ⚠️ **运行中 `create` 放进去的东西，GPU 传感器【看不见】** ——
> 障碍物 / 地图要写进**世界文件**（**坑 79**）。
>
> **`create` 放进去的模型只存在于这一次运行里** —— 重启 `gz sim` 就没了。

### 看 Gazebo 侧：`gz` 系列

**ROS 2 侧的查看命令是 `ros2 node / topic / service`；Gazebo 侧的对应物是 `gz`。**

```bash
gz topic -l                             # 列出 gz 侧所有话题
gz topic -e -t /scan                    # 打印某个话题的数据（会一直刷，Ctrl+C 停）
gz model --list                         # ★ 世界里现在有哪些模型
gz service -l                           # 列出 gz 侧所有服务
gz sdf -p <文件.urdf>                    # ★ 看 URDF → SDF 的转换结果
```

| 命令 | 干什么 | 什么时候用 |
|---|---|---|
| `gz topic -l` | 看 gz 侧有哪些话题 | 判断"Gazebo 那边到底有没有这个话题" |
| `gz topic -e -t <话题>` | 看话题上流的**原始数据** | 和 `ros2 topic echo` 对照：是"gz 没发"还是"bridge 没翻" |
| `gz model --list` | **看世界里到底有什么模型** | ★ **验证事实的硬手段**（`create` 报成功之后必查）|
| `gz service -l` | 看 gz 的服务 | 确认 `/world/.../create` 这类服务在不在 |
| `gz sdf -p <urdf>` | **看 URDF 转成 SDF 之后长什么样** | ★ 改了 URDF 没生效时，看"转换产物"是什么 |

> ⚠️ **`gz topic -e` 永不结束** —— **别在它后面接 `sort` / `wc`**（那些要等 EOF → 永远没输出）。
> **命令要"会自己结束"**：用 `head` 收尾，或者看完 `Ctrl+C`。
> **"命令怎么给才可靠"的三条规矩见 `10-原理与排查方法.md` §5.7。**
>
> ⚠️ **`gz sim` 不是 ROS 2 节点** —— **它不在 `ros2 node list` 里**。
> 两边是**两套话题图**，要分别用 `ros2 topic list` 和 `gz topic -l` 看。

### 一次雷达实验的"看事实"顺序

```bash
# ① 东西在不在
ros2 node list                    # bridge / robot_state_publisher 在吗
gz model --list                   # 世界里有机器人和障碍物吗

# ② 有人在发吗（两边分别看）
gz topic -l | grep scan           # gz 侧有 /scan 吗
ros2 topic hz /scan               # ROS 2 侧有数据在流吗

# ③ 数据本身对不对（都看"原始输出"，不加 --field、不加 grep）
ros2 topic echo /scan --once
gz topic -e -t /scan | head       # 看完 Ctrl+C

# ④ 怀疑"改了没生效" → 看转换产物
gz sdf -p ~/ros2_ws/src/my_robot_description/urdf/my_robot.urdf
```

> **"看不到 / 没数据"的完整检查法见 `10-原理与排查方法.md` §2.2（三层检查法）和 §4（按现象排错）。**

### 每次实验前：先清残留

```bash
pkill -f "gz sim"
pkill -f parameter_bridge
pkill -f robot_state_publisher
sleep 3
pgrep -a gz          # 确认没有输出
ros2 node list       # 确认是空的
```

> ⚠️ **`Ctrl+C` 掉 launch 之后，子进程不一定会全部退出** ——
> 残留的 bridge / rsp 会造出"**gz 侧有数据、ROS 2 侧没有**"这种看起来不可能的现象（**坑 80**）。
