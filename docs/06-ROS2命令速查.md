## 最常用的 6 条（先记这些）

```bash
# ① 启动乌龟窗口（虚拟机桌面终端里跑）
ros2 run turtlesim turtlesim_node

# ② 键盘遥控乌龟
ros2 run turtlesim turtle_teleop_key

# ③ 看现在有哪些节点
ros2 node list

# ④ 看现在有哪些话题
ros2 topic list

# ⑤ 编译你的代码（注意 --packages-select）
cd ~/ros2_ws && colcon build --packages-select my_turtle --symlink-install

# ⑥ 运行你自己写的程序
ros2 run my_turtle draw_circle
```

>
> | 场景 | 命令 |

> | **改接口**（`my_interfaces`）| `colcon build --packages-select my_interfaces` ← **不加** `--symlink-install` |

## 2.5 第 5 步：编译

```bash
cd ~/ros2_ws                     #  必须在工作空间【根目录】
colcon build --packages-select <包名> --symlink-install
```

**预期输出**：`Summary: 1 package finished`

> ⚠️ **为什么要加 `--packages-select`**（第 11 天踩的坑）：
> 工作空间里一旦有**接口包**（如 `my_interfaces`），
> **全量的 `colcon build --symlink-install` 会直接报错**：
> `existing path cannot be removed: Is a directory`。
>
> | 编什么 | 命令 |
> |---|---|
> | Python 包（`my_turtle`）| `--packages-select my_turtle --symlink-install` |
> | **接口包**（`my_interfaces`）| `--packages-select my_interfaces` ← **不加 flag** |
> | 全量 | `colcon build` |
>
> 详见 `08-踩坑总集.md` **坑 47**。

### 什么时候要重编

| 改了什么 | 重编？ |
|---|---|
| **已注册文件的【内容】**（`.py`、launch、config 都算）| ❌ **不用** |
| **新增文件**并注册到 `setup.py` | ✅ **要** |
| **`setup.py` 本身**（entry_points / data_files）| ✅ **要** |
| `package.xml` | ✅ 要 |
| **不确定** | ✅ **重编，几秒钟的事** |

**一句话：改【内容】不用重编；改【结构】要重编。**

> **为什么？** `--symlink-install` 让"已存在的文件"用**符号链接**指向源码 ——
> 所以你改源码内容，链接那边立刻就是新的。
> **但"新增文件"需要建立新的链接 → 必须重编。**
>
> **实测验证**（第 7 天）：改了 `square_demo.launch.py` 的**内容**（加 `parameters=`），
> **没重编直接跑，生效了** ✅

### 常用编译选项

| 选项 | 作用 |
|---|---|
| `--symlink-install` | 符号链接代替复制（**Python 包必加**）|
| `--packages-select <包名>` | 只编译指定的包 |
| `--cmake-clean-cache` | 清了重编（疑难杂症时用）|

### 验证资源文件装进去了没

```bash
ls ~/ros2_ws/install/<包名>/share/<包名>/config/
```

> **注册过 `data_files` 才看得到这里的内容**（launch 文件同理，在 `share/<包名>/launch/`）。
> 目录空的 = `setup.py` 没改对，或者改了没重编。
> **`setup.py` 该改哪一行见 `05-写节点清单.md` 第一部分第 7 步 ②。**

# 第三部分（§3）：命令分类速查

## 3.1 命令的通用结构

**ROS 2 的命令几乎都是这个形状：**

```
ros2  <类别>  <动作>  [参数...]
       └─┬─┘  └─┬─┘
     操作什么   怎么操作
```

**举例：**

| 命令 | 类别 | 动作 |
|---|---|---|
| `ros2 node list` | node（节点）| list（列出）|
| `ros2 topic echo /turtle1/pose` | topic（话题）| echo（打印内容）|
| `ros2 service call ...` | service（服务）| call（调用）|
| `ros2 pkg executables turtlesim` | pkg（包）| executables（列出程序）|

**记住这个结构，你就能"猜"出命令。**

> **忘了有什么动作？** 只敲类别，它会列出所有可选动作：
> ```bash
> ros2 topic          # 回车，列出 topic 下所有动作
> ros2 node --help    # 看详细帮助
> ```

---

## 3.2 启动类命令（天天用）

### 启动任意一个程序

```bash
ros2 run <包名> <程序名>
         └──┬─┘ └──┬──┘
        哪个包   包里的哪个程序
```

| 例子 | 干什么 |
|---|---|
| `ros2 run turtlesim turtlesim_node` | **启动乌龟窗口** |
| `ros2 run turtlesim turtle_teleop_key` | 键盘遥控乌龟 |
| `ros2 run turtlesim draw_square` | 官方的画正方形程序 |
| `ros2 run my_turtle draw_circle` | **你自己写的转圈节点** |
| `ros2 run my_turtle read_pose` | 你自己写的读位置节点 |

>  **`turtlesim_node` 有图形界面，必须在【虚拟机桌面终端】跑**
> VS Code 的 SSH 终端没有显示环境，会报 `cannot open display`。
> 纯计算的节点（如 `draw_circle`）没这个限制。

### 用 launch 文件启动（一次起多个节点 + 传参）

```bash
ros2 launch <包名> <launch文件名>
```

**一次启动一整个场景**（节点 + 参数 + 顺序），比开好几个终端 `ros2 run` 省事。

**实例（都是你自己写的）：**

```bash
ros2 launch my_turtle square_demo.launch.py     # 第 7 天：turtlesim + draw_square
ros2 launch my_turtle circle_demo.launch.py     # 第 10 天：带 circle_params.yaml 参数
ros2 launch my_turtle polygon_demo.launch.py    # 第 13 天：一次起 3 个节点
```

> **launch 文件名必须是【完整文件名】**（含 `.launch.py`），和 `ros2 run` 只写程序名不一样。
>
> **前提**：launch 文件要先在 `setup.py` 的 `data_files` 里**注册**，再**重编 + `source`**
> —— **没注册就 `ros2 launch` 看不见它**（见 `05-写节点清单.md` 第一部分第 7 步 ②）。

## 3.3 查看类命令（探索和排错）

### 节点 (Node)

```bash
ros2 node list                  # 列出所有正在运行的节点
ros2 node info /节点名           # 看这个节点的详细接口
```

**`ros2 node info` 会显示：** Subscribers / Publishers / Service Servers / Action Servers

### 话题 (Topic)

```bash
ros2 topic list                 # 列出所有话题
ros2 topic list -t              # 连带显示消息类型
ros2 topic echo /话题名          # 打印话题上的数据（会一直刷）
ros2 topic echo /话题名 --once   # 只打印一条
ros2 topic hz /话题名            # 测发布频率
ros2 topic info /话题名          # 谁在发、谁在收
ros2 topic pub /话题名 类型 "内容"  # 手动往话题发消息
```

**`ros2 topic pub` 示例：**

```bash
ros2 topic pub -r 10 /turtle1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 2.0}}"
```

| 部分 | 含义 |
|---|---|
| `-r 10` | 每秒发 10 次（不加的话默认每秒 1 次）|
| `--once` | 只发一次就退出 |

### 服务 (Service)

### 查看

```bash
ros2 service list               # 列出所有服务
ros2 service list -t            # 连带显示服务类型
ros2 service type /服务名        # 查某个服务是什么类型
ros2 service list | grep 关键词   # 筛选（找自己的服务）
```

### 查有哪些服务类型可用

```bash
ros2 interface list | grep "/srv/"        # 列出所有服务类型
ros2 interface show std_srvs/srv/SetBool  # 看某个类型长什么样
```

### 调用服务

```bash
ros2 service call <服务名> <服务类型> "<请求内容>"
         └──┬──┘ └──┬──┘ └───┬───┘ └────┬────┘
          命令   调用   哪个服务   它的类型    请求内容
```

| 类型 | 请求内容怎么写 |
|---|---|
| `std_srvs/srv/Empty`（请求是空的）| **不用写**，命令到此结束 |
| `std_srvs/srv/SetBool` | `"{data: true}"` 或 `"{data: false}"` |
| `std_srvs/srv/Trigger`（请求是空的）| **不用写** |
| `turtlesim/srv/Spawn` | `"{x: 8.0, y: 8.0, theta: 0.0, name: 'xx'}"` |

>  **命令行里的布尔值写小写 `true` / `false`**（YAML 写法），
> **Python 代码里写大写 `True` / `False`**。

### 常用服务调用实例

```bash

# 乌龟瞬移

ros2 service call /movemove std_srvs/srv/SetBool "{data: true}"    # 让乌龟走
ros2 service call /movemove std_srvs/srv/SetBool "{data: false}"   # 让乌龟停

# 调用自己写的服务（第 4 天的 greeter）
ros2 service call /say_hello std_srvs/srv/Trigger
```

### 三个标准服务类型速查

| 类型 | `---` 上面（请求）| `---` 下面（响应）| 用在 |
|---|---|---|---|
| `std_srvs/srv/Empty` | （空）| （空）| 只要触发，不要参数不要结果 |
| `std_srvs/srv/Trigger` | （空）| `bool success`<br>`string message` | 触发 + 要结果 |
| `std_srvs/srv/SetBool` | `bool data` | `bool success`<br>`string message` | 设置一个开关 |

### 动作 (Action)  第 9 天补充

> **动作 = 服务（目标/结果）+ 话题（反馈）+ 状态管理（可取消）**
> 适合**长任务**：能实时看进度、能中途取消。

### 查看

```bash
ros2 action list                      # 列出所有动作
ros2 action list -t                   # 连带显示动作类型
ros2 action info /动作名               # 谁在提供、谁在调用
ros2 interface show <动作类型>         # 看格式
ros2 interface list | grep "/action/" # 列出所有动作类型
```

**实例：**
```bash
ros2 action list -t
# 预期：/turtle1/rotate_absolute [turtlesim/action/RotateAbsolute]

ros2 interface show turtlesim/action/RotateAbsolute
# 预期：
# float32 theta        ← 目标 goal
# ---
# float32 delta        ← 结果 result
# ---
# float32 remaining    ← 反馈 feedback
```

### 调用动作（命令行）

```bash
ros2 action send_goal <动作名> <动作类型> "<目标内容>" --feedback
```

| 部分 | 含义 |
|---|---|
| `send_goal` | 发送目标（不是 `call`！）|
| `--feedback` | **加它才能看到实时反馈** |

**实例：**
```bash
ros2 action send_goal /turtle1/rotate_absolute turtlesim/action/RotateAbsolute "{theta: 1.5708}" --feedback
```

**预期：**
| 现象 | 说明 |
|---|---|
| 乌龟转动到 90° | 目标执行中 |
| 终端持续打印 `feedback: remaining=...` | **实时反馈**（数值递减）|
| 最后打印 `result: delta=...` | 完成，返回结果 |

### 动作文件的格式（两条 `---` 分三段）

```
float32 theta        ← 目标 goal      （第一条 --- 上面）
---
float32 delta        ← 结果 result    （两条 --- 之间）
---
float32 remaining    ← 反馈 feedback  （第二条 --- 下面）
```

>  **顺序是：目标 → 结果 → 反馈**（不是"目标→反馈→结果"）
> **对比 `srv`：只有一条 `---`，两段（请求 / 响应）。**

### 三种通信机制速查

| | 话题 Topic | 服务 Service | **动作 Action** |
|---|---|---|---|
| 模式 | 发布/订阅 | 请求/响应 | 目标/反馈/结果 |
| 时长 | 持续 | 短 | **长任务** |
| 看进度 | — | ❌ | ✅ |
| 可取消 | — | ❌ | ✅ |
| 类比 | 广播电台 | 打电话 | **点外卖** |
| 命令行 | `topic pub` | `service call` | **`action send_goal`** |

```bash
ros2 interface show <完整类型名>              # 看某个类型长什么样
ros2 interface package <包名>                 # 看某个包定义了哪些接口
```

**示例：**


#### 怎么知道一个类型有哪些字段（从 `05` 第七部分迁来）

> **这是最常问的问题：`request` / `response` / `msg` 后面能接什么？**

**三个办法：**

| 办法 | 怎么做 | 什么时候用 |
|---|---|---|
| **① 查类型定义（最权威）** | `ros2 interface show <完整类型名>` | 想确认字段名 |
| **② VS Code 自动补全（最快）** | 代码里打 `request.` / `response.` / `msg.`，等列表弹出 | 写代码时 |
| **③ 列出所有类型** | `ros2 interface list \| grep "/srv/"`、`ros2 interface package <包名>` | 忘了类型名 |

**例：**

```bash
ros2 interface show std_srvs/srv/SetBool
```

**输出：**

```
bool data
---
bool success
string message
```

**从类型定义 → 代码里的字段名（关键映射）**

**规则：类型定义里的【每一行】= 一个字段。字段名就是"类型后面那个词"。**

**例 1：`msg` 类型（消息）—— 没有分隔线，全部给 `msg`**

```bash
ros2 interface show turtlesim/msg/Pose
```

```
float32 x
float32 y
float32 theta
float32 linear_velocity
float32 angular_velocity
```

代码里就能用：`msg.x` `msg.y` `msg.theta` `msg.linear_velocity` `msg.angular_velocity`

**例 2：`srv` 类型（服务）—— 注意中间的分隔线**

| 位置 | 内容 | 代码里怎么用 |
|---|---|---|
| `---` **上面** | `bool data` | **请求** → `request.data` |
| `---` **下面** | `bool success`<br>`string message` | **响应** → `response.success`<br>`response.message` |

**例 3：`Empty` 类型（空的）**

```bash
ros2 interface show std_srvs/srv/Empty
```

**输出：什么都没有。**
所以**没有 `request.xxx` 可读，也没有 `response.xxx` 可填** ——
回调里什么都不用填，但 `return response` 还是要写。

**例 4：`Trigger` 类型**

```bash
ros2 interface show std_srvs/srv/Trigger
```

| 位置 | 内容 | 代码里 |
|---|---|---|
| `---` 上面 | （空）| **请求没字段可读** |
| `---` 下面 | `success`、`message` | `response.success`、`response.message` |

**一句话记忆：**

> **想知道 `request` / `response` / `msg` 能接什么 → 跑一次 `ros2 interface show <类型>`。**
> **`---` 上面给 `request`，下面给 `response`；消息（msg）没有分隔线，全部给 `msg`。**

**连带的：怎么知道自己该用哪个类型**

```bash
# 看某个话题用的是什么类型
ros2 topic list -t

# 看某个节点发布了/订阅了什么类型
ros2 node info /节点名

# 看某个服务用的是什么类型
ros2 service type /服务名
```

> **写代码时怎么用这些字段**（造消息 / 填字段 / 读字段）见 `05-写节点清单.md` **形状 5、6、9**。

## 3.5 几条相似的命令，对照记

**它们结构一样，只是"发什么"不同：**

```bash
ros2 run            <包名> <程序名>
ros2 topic pub      <话题名> <消息类型> "<内容>"
ros2 service call   <服务名> <服务类型> "<请求内容>"
ros2 action send_goal <动作名> <动作类型> "<目标内容>" [--feedback]
```

| 命令 | 通信方式 | 特点 |
|---|---|---|
| `ros2 run` | 启动一个程序 | 启动后一直运行 |
| `ros2 topic pub` | **发布**（单向广播）| 一直发（除非 `--once`）|
| `ros2 service call` | **调用**（一问一答）| **发一次，等回复，结束** |
| `ros2 action send_goal` | **发目标**（长任务）| **能看反馈（`--feedback`）、能取消** |

**记忆锚点：**

> **`pub` = 广播，发完就走**
> **`call` = 打电话，等对方回复**
> **`send_goal` = 点外卖，能看骑手到哪了、能取消**

### 三个"查看类型"的命令也平行

```bash
ros2 topic list -t              # 话题 + 消息类型
ros2 service list -t            # 服务 + 服务类型
ros2 action list -t             # 动作 + 动作类型
```
```bash
ros2 interface list | grep "/msg/"       # 所有消息类型
ros2 interface list | grep "/srv/"       # 所有服务类型
ros2 interface list | grep "/action/"    # 所有动作类型
```

### 命令类报错

| 报错 | 原因 | 解决 |

| `Package 'xxx' not found` | 终端没 source 工作空间 | `source ~/ros2_ws/install/setup.bash` |
| `No executable found` | 程序名写错，或改了 setup.py 没重编 | 查 `ros2 pkg executables <包名>`；重编 |
| `the following arguments are required` | 命令参数少给了 | 看报错里的 `usage:` 那一行，看缺哪个 |
| `cannot open display` | 在 SSH 终端跑图形程序 | 改用虚拟机桌面终端 |

### Python 报错

| 报错 | 原因 | 解决 |
|---|---|---|
| `AttributeError: 'Greeter' object has no attribute 'operation'` | **回调函数没缩进到类里**，或类里没这个方法 | 检查缩进；用 VS Code 折叠功能验证 |
| `AttributeError: ... has no attribute 'publisher_'` | **存的名字和用的名字不一致** | 存 `self.publisher_` 就得用 `self.publisher_` |
| `AttributeError: ... has no attribute 'messsage'` | **字段名拼写错误** | 用 VS Code 自动补全（打 `response.` 看列表）|
| **`UnboundLocalError: ... local variable 'xxx'`** | **忘了写 `self.`** | 引用自己类里方法/属性必须加 `self.` |
| `NameError: name 'xxx' is not defined` | 用了没导入的名字 | 检查文件开头的 import |
| `TypeError: ... takes N positional arguments` | 函数参数个数不对 | 对照形状模板数参数 |
| `IndentationError` | 缩进不对 | 同类方法左边对齐（缩进 4 格）|
| **`Assertion 'PyFloat_Check' failed` + `Aborted`** | **浮点字段赋了整数** | `2` → `2.0`，`0` → `0.0` |

### 没有报错但行为不对

| 现象 | 可能原因 | 怎么查 |
|---|---|---|
| **服务调用卡住不返回** | 回调**忘了 `return response`** | 看回调最后一行 |
| **服务列表里找不到自己的服务** | 服务名写错（常见：把类型当名字）| `ros2 service list` 看实际叫什么 |
| **乌龟不动** | ① 初始状态就是"停"，**要先调用服务**<br>② `self.moving` 没被设成 True | `ros2 topic echo /turtle1/cmd_vel --once` 看 x 是几 |
| **改了代码没生效** | 改了结构但没重编 | `colcon build --packages-select <包名> --symlink-install`（**改接口时不加 flag** —— 见坑 47）|
| **`ros2 node list` 里没有我的节点** | 节点已崩溃退出 | 看终端有没有报错 |
