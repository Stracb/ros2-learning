# 二、`__init__` —— 准备阶段

```python
def __init__(self):
    super().__init__('draw_square')                    # ① 起名字

    self.publisher_ = self.create_publisher(           # ② 建发布者
        Twist, '/turtle1/cmd_vel', 10
    )

    self.subscriber_ = self.create_subscription(       # ③ 建订阅者
        Pose, '/turtle1/pose', self.operation, 10
    )

    self.state = 'forward'                             # ④ 状态机初始状态
    self.start_x = None                                # ⑤ 起点（还不知道）
    self.start_y = None

    self.get_logger().info('初始化成功')                # ⑥ 打个招呼
```

| # | 代码 | 干什么 |
|---|---|---|
| ① | `super().__init__('draw_square')` | 给节点起名 |
| ② | `create_publisher` | 建"发信箱"——往 `/turtle1/cmd_vel` 发速度 |
| ③ | `create_subscription` | 订报纸——收 `/turtle1/pose`，收到就调 `operation` |
| ④ | `self.state = 'forward'` | **状态机起点：一开始是"直行"** |
| ⑤ | `self.start_x = None` | **起点还不知道** —— 等第一条位置消息 |
| ⑥ | 日志 | 确认启动了 |

## 状态变量一览（都放在 `self.` 上）

| 变量 | 作用 | 类型 |
|---|---|---|
| `self.state` | **记住"现在在干什么"** | `'forward'` / `'turn'` / `'done'` |
| `self.start_x/y` | 记住"从哪个点开始量的" | 浮点 / `None` |
| `self.start_theta` | 记住"从哪个朝向开始转的" | 浮点 |
| `self.side_count` | 记住"画了几条边" | 整数 |

> ⚠️ **为什么必须用 `self.`？**
> 局部变量函数结束就没了；**`self.xxx` 只要节点活着就一直在**。
> **状态机必须跨多次回调保持记忆 → 必须用 `self.`**

# 三、`operation` —— 核心逻辑（分五段）

```python
def operation(self, msg):
    # ═══ 第 1 段：首次初始化 ═══
    if self.start_x is None:
        self.start_x = msg.x
        self.start_y = msg.y
        self.get_logger().info(f'起点: ({msg.x:.2f}, {msg.y:.2f})')

    # ═══ 第 2 段：测量误差 ═══
    dist = math.hypot(msg.x - self.start_x, msg.y - self.start_y)

    # ═══ 第 3 段：造一条空的指令容器 ═══
    cmd = Twist()

    # ═══ 第 4 段：状态机（决策）═══
    if self.state == 'forward':
        ...
    elif self.state == 'turn':
        ...
    else:                     # 'done'
        ...

    # ═══ 第 5 段：发出去（只有这一处！）═══
    self.publisher_.publish(cmd)
```

## 设计好在哪

| 设计 | 好处 |
|---|---|
| **先测量，再决策** | 逻辑清晰 |
| **`cmd` 只造一次** | 三个分支往里填 |
| **`publish` 只写一处** | 加新分支时不用记得发 |

> **"最后统一发一次"**是好习惯 —— 和 `PubSub` 里用的一样。

# 四、状态机详解 ⭐

## 状态图

```
        ┌─────────────────────────────────────────┐
        │                                         │
        ▼                                         │
  ┌─────────────┐   dist ≥ 1.5    ┌─────────────┐ │ side_count < 4
  │  'forward'  │ ───────────────▶│   'turn'    │─┘
  │             │                 │             │
  │ cmd.linear  │                 │ cmd.angular │   side_count ≥ 4
  │   .x = 1.0  │                 │   .z = 0.3  │───────────┐
  └─────────────┘                 └─────────────┘           ▼
                                                     ┌─────────────┐
                                                     │   'done'    │
                                                     │  cmd 全 0   │
                                                     └─────────────┘
```

## 每个状态干什么

| 状态 | 发什么指令 | 什么时候切走 |
|---|---|---|
| **`'forward'`** | `cmd.linear.x = 1.0`（往前走）| `dist >= 1.5`（走够 1.5 米）|
| **`'turn'`** | `cmd.angular.z = 0.3`（原地转）| `dtheta >= π/2`（转够 90°）|
| **`'done'`** | `cmd.linear.x = 0`、`cmd.angular.z = 0` | 不切了 |

## ⚠️ 状态切换有两个"副作用"

**切换状态时不只是改 `self.state`，还要做配套的事：**

```python
# forward → turn 时：
self.state = 'turn'
self.start_theta = msg.theta        # ← 记下"转弯从哪个朝向开始"

# turn → forward 时：
self.state = 'forward'
self.start_x = msg.x                # ← 记下"新边从哪开始"
self.start_y = msg.y
```

**不做这个配套动作就会出 bug**（用户两次都踩到）：
- 忘记 `start_theta` → 转弯角度不对
- 忘记 `start_x` → 后面的边一步都不走

# 五、两个测量机制

## ① 测距离 —— "离起点多远了"

```python
dist = math.hypot(msg.x - self.start_x, msg.y - self.start_y)
```

```
       起点 ●
            │╲
            │  ╲  ← dist = 这条斜边
            │    ╲
            └──────●  当前位置
```

**`math.hypot(a, b)` = `√(a² + b²)`** —— 勾股定理。

## ② 测角度 —— "从起始朝向转了多少"

```python
dtheta = abs(msg.theta - self.start_theta)
```

**`math.pi/2` = 1.5708 弧度 = 90°**（第 1 天手工敲过的数字）

# 六、一条贯穿全篇的规律 ⭐

> ## **进入一个新状态时，必须把"这个状态需要用到的起点值"一起记下来。**

| 进入哪个状态 | 必须记什么 | 在哪记 |
|---|---|---|
| **一开始**（首次回调）| `start_x` / `start_y` | `if self.start_x is None:` 块 |
| **`'turn'`** | `start_theta` | `state = 'turn'` 旁边 |
| **回到 `'forward'`** | `start_x` / `start_y` | `state = 'forward'` 旁边 |

**为什么？** 因为每个状态都在"从某个起点算差值"：

```
'forward' 算的是：从起点走了多远
'turn'    算的是：从起始朝向转了多少
```

**起点不更新，差值就是错的。**

> **这条规律适用于所有"基于反馈的控制程序"** —— 不止画正方形。

# 七、一次完整的运行时序

```
时间 ──▶

第 1 次回调：
  start_x = None → 记起点 (5.54, 5.54)
  dist = 0  →  state='forward' → 发 linear.x=1.0

第 2 次回调：
  dist = 0.05  →  继续发 1.0

  ...（重复几十次，乌龟往前走）...

第 N 次回调：
  dist = 1.52 ≥ 1.5  →  state='turn'
                        start_theta = 当前朝向（如 0.0）

第 N+1 次回调：
  state='turn' → dtheta = 0.03 < 1.57 → 发 angular.z = 0.3

  ...（重复十几次，乌龟原地转）...

第 M 次回调：
  dtheta = 1.60 ≥ 1.57 → side_count += 1
                         state='forward'
                         start_x / start_y = 当前位置

  ...（重复以上全过程 4 次）...

第 4 次转完后：
  side_count = 4 → state='done' → 发全 0，乌龟停下 ✅
```

# 八、这个结构的通用性

**把"乌龟/正方形"换成别的东西，结构完全不变：**

| 你的程序 | 通用形式 |
|---|---|
| 订阅 `/turtle1/pose` 收位置 | **读传感器** |
| `dist` / `dtheta` 算误差 | **算误差** |
| `if state == ...` 决策 | **决策** |
| 发 `Twist` 到 `/cmd_vel` | **发控制指令** |

**这就是「感知 → 决策 → 控制」的闭环。**

| 系统 | 传感器 | 控制指令 |
|---|---|---|
| 画正方形 | 乌龟位置 | 速度和转向 |
| 扫地机器人 | 激光雷达 | 轮子速度 |
| 无人机 | IMU + 视觉 | 电机转速 |
| 自动驾驶 | 雷达 + 摄像头 | 油门/刹车/方向盘 |

**骨架一模一样。这个程序是它们的微缩版。**

# 十、踩过的坑

| # | 现象 | 根因 | 教训 |
|---|---|---|---|
| 1 | 转弯角度不对（转多了）| `start_theta` 硬编码成 `0.0`，没在切状态时记 | **进新状态要记起点** |
| 2 | 过冲 6°（每边不闭合）| 离散检查 —— 两次检查之间还在转 | **过冲 ≈ 角速度 × 检查间隔** |
| 3 | 后面几条边不走 | 回 `'forward'` 时没更新 `start_x/y` | **同上** |
| 4 | `cmd.linear.z` 写错 | 应该是 `cmd.angular.z` | 分清 `linear`（平移）和 `angular`（旋转）|
| 5 | 首尾不闭合 | 4 个角各差几度，**累积** | **累积误差** —— 真实机器人学的核心问题 |

## ⭐ 关于第 5 条：累积误差

```
每个角过冲约 3°  ──┐
第 2 个角再过冲 3° ├──▶ 累积 12°  →  首尾差一点点
第 3 个角再过冲 3° │
第 4 个角再过冲 3° ┘
```

**解法**：减小角速度（用户自己试出来的 —— 让过冲小于肉眼可见）。

**这是真实机器人的核心问题**（轮子打滑、里程计漂移），
**第 10 周学 SLAM 时会再遇到** —— SLAM 的核心目的就是"用外部观测消除累积误差"。

> **一句话总结这份代码**：
> **一个"读位置 → 算误差 → 按状态决策 → 发速度"的闭环控制器。**
> **状态机负责"现在该干什么"，测量负责"干够了没有"，`self.` 负责"记住进度"。**
