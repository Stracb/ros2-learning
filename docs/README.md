## 代码放在哪

在虚拟机内部的工作空间 `~/ros2_ws`，目前有三个包：

| 包 | 类型 | 内容 |
|---|---|---|
| `my_turtle` | `ament_python` | 13 个练习节点，学习过程都记在这里 |
| `my_interfaces` | `ament_cmake` | 自定义接口，msg / srv / action 三件套齐全 |
| `my_robot_description` | `ament_cmake` | 机器人模型与仿真资产（URDF、桥接配置、世界文件、launch）|

第三个包是仿真那部分。**一条命令就能起一整套**（Gazebo + 机器人 + 数据桥）：

```bash
ros2 launch my_robot_description gazebo.launch.py
```

## 快速开始

```bash
hostname -I                                                 # ① 看虚拟机 IP（NAT 会变）
cd ~/ros2_ws && colcon build && source install/setup.bash    # ② 编译 + 加载工作空间
ros2 run turtlesim turtlesim_node                            # ③ 跑乌龟（另开终端跑自己的节点）
ros2 launch my_robot_description gazebo.launch.py            # ④ 起仿真：Gazebo + 车 + 桥
```

编译命令怎么选、自己的节点怎么跑 → [06-ROS2命令速查.md](06-ROS2命令速查.md) 第二部分。

## 踩了很久的一个坑：Gazebo 的渲染引擎要分开设

**症状**：`gz sim` 能启动、不报错，但 3D 视图一直频闪；
或者界面不闪了，**激光雷达的数据却全是 `range_min`**。

**原因**：`gz sim` 的 GUI 和服务器需要**不同的**渲染引擎 ——
GUI 要用 `ogre`（VMware 的虚拟显卡跟 `ogre2` 不兼容，所以会闪），
服务器要用 `ogre2`（GPU 传感器靠它渲染，用 `ogre` 就"看不见"）。

**正确写法**：

```python
'gz_args': '--render-engine-gui ogre --render-engine-server ogre2 -r <世界文件>'
```

不要写全局的 `--render-engine`（它会把两边一起改掉），
也不要改 `server.config`（那个文件里没有放引擎设置的位置）。

> 排查过程见 [08-踩坑总集.md](08-踩坑总集.md) 坑 72 / 坑 76；原理见 [10-原理与排查方法.md](10-原理与排查方法.md) §4.6。

## 环境是怎么变成现在这样的

第 1 天用的是 Ubuntu 22.04 + ROS 2 Humble，但有两个问题：
只有 4 GB 内存，Gazebo + RViz 起步就要 6–8 GB，根本跑不动；
Humble 默认搭配的 Gazebo Classic 也已经停止维护。

当时还没开始学，沉没成本为零，就直接换了新环境。旧虚拟机删掉后回收了约 50 GB。
